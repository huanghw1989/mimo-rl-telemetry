## 一、摘要：六条结论

1. **两个 run 的数据集清单完全相同：25 个，分 5 类**（code 11、general 4、visual 6、chat 3、cyber 1）。pro 的 cyber 一共 42 个指标**全部**在第 14 步之后同时停报，公告时间（2026-09-17T12:20:11Z）正好落在第 14 步和第 15 步的墙钟之间——"移除 cyber"这件事在数据里是闭合的。【我方实测】

2. **谁在被学会，逐数据集看差别极大。** pro 是「6 个明显学会 / 6 个缓慢改善 / 7 个停滞 / 4 个退化」，flash 是「9 / 8 / 3 / 3」（另有 2 个数据集因通过率含疑似未上报的 0 无法分类）。pro 涨得最多的是 `visual/dataset-jzd3`（+15.36pp）、`general/dataset-1doa`（+15.17pp）、`code/dataset-m1dt`（+14.10pp）；退得最多的是 `code/dataset-4onq`（−10.14pp）、`chat/dataset-lm3t`（−9.78pp）、`code/dataset-v7yx`（−9.17pp）。**同一个数据集在两个 run 上的涨幅秩相关 ρ=0.582（n=25，p=0.0023）**，说明这个异质性是可复现的，不是单次噪声。【我方实测】

3. **核心问题的答案：没有辛普森式污染，配比挪动反而是拖累。** 把总体通过率按 `dynsam/<cat>/dataset-<id>/num_accepted/step`（该数据集这一步受理进训练 batch 的题数）加权重构，做精确三项分解：pro 的总变化 +3.54pp 里，"各数据集自己变好"贡献 **+3.81pp（107.6%）**，配比项只有 **+0.16pp**，交互项 −0.43pp，两项合计 **−0.27pp（占总变化的 −7.6%）**；flash 的总变化 +9.15pp 里"自己变好"是 **+8.31pp（90.8%）**，配比项 +0.008pp、交互项 +0.835pp，合计 **+0.84pp（+9.2%）**。**结论：成绩的总量提升 91%~108% 来自各数据集自身变好，权重挪动最多解释 9%，而且 pro 上方向还是负的。**【我方实测】

4. **但"生成长度"这个总量指标不一样，它被配比污染得更重。** 同样的算法作用在 `ctx_response_length/mean` 上：pro 的总长增长 +58110 token 里 8.3%（+4818）、flash 的 +94262 里 **23.4%**（+22067）来自权重挪向更长的数据集。**同一个"总量指标"上，成绩几乎干净、长度不干净。**【我方实测】

5. **"长度涨了成绩也涨"只在一个角落里成立。** 25 个数据集 × 2 个 run 里，水平回归和差分回归**同时显著为正**的只有 3 例：`visual/dataset-jzd3`@pro（差分 +9.65pp/万 token，p=0.010）、`visual/dataset-ve5o`@pro（+1.85，p=6.8e-5）、`visual/dataset-ve5o`@flash（+0.63，p=0.011）。**显著相反**（长度涨、差分意义上成绩显著下降）有 5 例：`chat/dataset-eup7`@pro、`cyber/dataset-9aui`@pro、`cyber/dataset-9aui`@flash、`general/dataset-epqd`@pro、`visual/dataset-pt5v`@flash。其余 27 例**差分不显著**——包括所有 code 类数据集。【我方实测】

6. **数据集之间没有可靠的"先后顺序"。** 全部数据集两两之间的差分互相关，在 lag = −4…+4 上的平均相关系数绝对值都 ≤0.022（每个 lag 297~300 对）；净领先分最高与最低只差 7（pro）和 9（flash），对手数是 24 个，符号检验 p 最小也只有 0.064。唯一像方向性的东西是 flash 的"期初越难、突破越晚"（ρ=0.434，n=23，p=0.039），pro 上同样算法只有 0.069（p=0.78）——**两个 run 不一致，我不把它当课程结构的证据**。【我方实测】

### 2.1 分类规则（写死在脚本里，可直接核对）

记 Δpp = 最后一个有值步 − 第一个有值步（pp），b = 通过率对步号的 OLS 斜率（pp/步），p 为其双尾 p 值：

1. **退化**：Δpp ≤ −3.0 或（b < 0 且 p < 0.05）
2. **明显学会**：b > 0 且 p < 0.05 且 Δpp ≥ +5.0
3. **缓慢改善**：（b > 0 且 p < 0.05 且 Δpp < +5.0）或（b > 0 且 0.05 ≤ p < 0.20 且 Δpp > 0）
4. **停滞**：其余
5. 另有 **不可靠（哨兵 0）**：`visual/dataset-gtav`、`visual/dataset-ol8x`，规则不适用

规则 1 优先于 2/3/4，所以"首末差很大但斜率完全不显著"的数据集会落进退化——它们在 JSON 里带 `classNote` 标记（pro 有 `code/dataset-4onq`、`code/dataset-v7yx`、`chat/dataset-lm3t`，flash 有 `chat/dataset-eup7`），读者不要把这类当成"真的在退步"。

### 2.2 三项 shift-share 分解（§五用的核心工具）

对同一批数据集的两期，记 s 为按权重归一化后的份额（Σs = 1），则

```
ΔA = Σ s_d(0) · Δp_d          ← 自身变好（按基准配比计价）
   + Σ Δs_d · p_d(0)          ← 配比挪动（按基准成绩计价）
   + Σ Δs_d · Δp_d            ← 交互项
```

三项之和**精确**等于 ΔA（脚本里输出 `checkSumError`，实测为 0）。之所以不用"固定配比曲线之差"单独下结论，是因为那个差等于「配比项 + 交互项」，把"挪过去的那些数据集同期也在变好"这件事混进了配比里。两种口径在 §五都给。

### 2.3 做不了的事（先讲清楚）

- **每个数据集的"16 次一次都没做对"占比没有上报。** 全库只有全局的 `dynsam/passrate/zero`（全错题占比），数据集层只有平均通过率。所以问题 2 里"那道墙在哪个数据集上"只能用**平均通过率最低**和**低分区停留时长**这两个替代读数，这一点在 §四里明确标注。
- **`train/passrate/passrate_0_ratio` / `passrate_1_ratio` 在 109 条中文解读里没有条目**，我无法确认它们在数什么（详见 §十）。

### 3.4 一个够硬的口径发现：疑似"未上报"的 0 全部落在重启步上

`visual/dataset-gtav` 和 `visual/dataset-ol8x` 的精确 0 出现的位置**不是随机的**：

| run | 精确 0 出现的步 | 数量 | 同一时刻 `critic/.../score/mean` 的值 |
|---|---|---|---|
| pro | 1, 2, 3, 11, 15, 17, 23 | 各 7 次 | gtav 0.53~0.57、ol8x 0.60~0.67（都是正常值） |
| flash | 1, 3, 16, 25, 28 | 各 5 次 | gtav 0.52~0.59、ol8x 0.63~0.67 |

pro 的 `events[]` 给出的重启受影响步是 **3, 11, 15, 17, 23**，flash 是 **16, 25, 28**（flash 另有一次重跑在第 16、17 步）。把两张表对起来：**精确 0 的集合 = 第 1 步 ∪（第 2 步，仅 pro）∪ 全部重启受影响步**，一个不多一个不少。

同一时刻 `critic/<cat>/dataset-<id>/score/mean` 是正常值，说明这些题**并没有真的 0% 通过**，只是通过率这一族没报上来。这比 `notes/09` 里"怀疑是未上报哨兵"的推断更进一步：它不是零散漏报，而是**跟重启绑定的成片缺报**。

> **可迁移概念 1｜重启耦合的上报缺口（restart-coupled reporting gap）**
> 定义：某些指标在运维重启后的第一个上报步整族缺值，但同一实体、同一时刻的其它指标族照常有值。判断方法：把"缺值步集合"和"重启事件步集合"求交集，如果缺口是重启步的超集，就是口径问题而不是数据问题。
> 本文体现：gtav/ol8x 的通过率 0 在 pro 命中 5/5 个重启步、flash 命中 3/3 个重启步，且同期 `critic` score 正常。
> 可迁移规则：**看到"某个切片突然大面积变成 0 或缺失"，先按时间对齐运维事件；如果缺值只出现在事件步上，就别把它当业务信号，先把它从趋势统计里剔掉。**

> 本文体现：全局 `passrate/zero` 全程钉在 13%~17%（pro 只降 1.14pp），同期全局 `avg@n` 涨了 6.88pp（pro）/12.71pp（flash）——**涨的全是"半会"的题变成"全对"，"完全不会"的那块没被抬起来**。数据集层则只有平均通过率，看不到全错比例，所以我在 §4.3 用"低于 45% 的步占比"当替代读数，并明确标注这是替代品不是原指标。
> 可迁移规则：**评估一个训不动的切片时，先问"它的全错占比有没有降"而不是"它的平均分有没有涨"；平均分涨可能只是中段变好，全错占比不动意味着这个切片实际上没被学习。**

## 五、总量指标有没有被数据配比污染（问题 3，核心）

**结论**：**没有辛普森式污染。** 两个 run 的成绩总量提升里，配比挪动最多只占 9%（flash），pro 上还是 −7.6%（拖累）。但**生成长度这个总量指标被配比污染得多得多：pro 8.3%、flash 23.4%**。

**人话**：担心的是"平均分涨了，但只是因为训练越来越多地拿简单题来考"。数据说这没有发生。真正需要注意的是另一件事：整体"回答越来越长"这个结论里，有很大一块只是因为采样器把更多流量给了本来就写得长的数据集。

### 5.1 成绩总量：三项分解

| run | 口径 | 面板大小 | 总变化 | 自身变好（Σs₀Δp） | 配比项（ΣΔs·p₀） | 交互项（ΣΔs·Δp） | 配比+交互占总变化 |
|---|---|---|---|---|---|---|---|
| pro | 按 `num_accepted/step` 加权 | 22 | **+3.544pp** | +3.813（107.6%） | +0.162 | −0.431 | **−0.269pp（−7.6%）** |
| flash | 按 `num_accepted/step` 加权 | 23 | **+9.149pp** | +8.307（90.8%） | +0.008 | +0.835 | **+0.843pp（+9.2%）** |

面板 = 首末两步都有通过率且权重 > 0 的数据集（pro 22 = 25 − cyber − gtav − ol8x；flash 23 = 25 − gtav − ol8x）。pro 的 cyber 因为末步缺失而被排除，这是口径决定的，不是选择性剔除。

**稳健性**（全部写在同一个 JSON 段落里）：

| 口径 | pro 配比+交互 | flash 配比+交互 |
|---|---|---|
| 权重换 `num_accepted/held`（题池持有量） | −0.936pp（−32.5%） | +0.933pp（+10.1%） |
| 权重换等权 | 恒为 0（构造使然） | 恒为 0（构造使然） |

> **可迁移概念 3｜辛普森悖论与构成效应（composition effect / shift-share）**
> 定义：总体均值 = 各分组均值的加权平均。当**权重本身随时间变化**时，总体均值的变动可以完全由"权重挪动"产生，甚至与每个分组的真实变化方向相反——这就是辛普森悖论在时间序列上的形态。标准的检验方式是三项 shift-share 分解：`ΔA = Σ s₀Δp（自身变好）+ Σ Δs·p₀（配比）+ Σ Δs·Δp（交互）`，三项精确加和。
> 本文体现：pro 总体通过率 +3.54pp，分解后 +3.81pp 来自各数据集自己变好、配比 −0.27pp；把权重换成 `held`、等权、或改变哨兵处理，配比项始终不超过 1pp。
> 可迁移规则：**看到"大盘指标在涨"，先做两件事——(1) 找出这个大盘的权重是什么、它是否在变；(2) 冻结第一期的权重重算一遍大盘曲线。如果冻结后曲线走向不变，涨是真的；如果翻转，涨就是构成效应。** 顺带一条：连"长度"这种看似纯模型行为的指标也要做这个检验，本文里它的构成效应比成绩大 3 倍。

## 六、每数据集的"长度—成绩"弹性（问题 4）

**结论**：水平回归里 14 个 run×数据集过了 0.05（pro 6 正 + 1 个不可靠的负，flash 8 正，其中 `x7wh`@pro 属伪显著），但**一阶差分后只剩 3 个仍显著为正、5 个显著为负，其余全部不显著**。所以"长度涨 → 成绩涨"在数据集这一层**基本不成立**。

**人话**：把两列都在上涨的曲线画在一起当然会看到正相关；但真正能回答"长度多涨一点、成绩是否跟着多涨一点"的是差分回归，答案是：大多数数据集没有关系。

### 6.1 口径

- 自变量 x = `ctx_response_length/mean` / 10000，即"每多 1 万 token"；因变量 y = 通过率（pp）。斜率单位是 **pp / 万 token**。
- 水平回归用全部有值步（pro 24、flash 30；cyber 用 14）；差分回归用相邻步之差（n 少一个）。
- 杠杆稳健性：去掉长度离均值最远的那一个点后重跑水平回归；若显著性消失，标为"伪显著"。
- `visual/dataset-053e` 没有任何长度数据 → 做不了；`visual/dataset-gtav`/`ol8x` 通过率不可靠 → 结论标为不可靠；`gtav` 用 `ctx_total_length/mean` 做回退口径（已在 JSON 的 `lenKind` 里标注）。
- **chat 类要单独当心**：`chat/dataset-eup7` 的长度在 flash 里跨 18.9 倍、`lm3t` 跨 27.8 倍，而且没有趋势（lm3t flash 的长度序列 1580→683→…→18977），水平回归的显著性很容易被单个高杠杆点制造出来。

| `code/dataset-yfch` | 1.45e-3 | **2.22e-3** | 1.79e-3 | **2.60e-3** |
| `cyber/dataset-9aui` | 7.05e-4 | 1.10e-3 | 6.40e-4 | 1.03e-3 |
| 第三个（pro：`visual/dataset-ve5o`；flash：`code/dataset-m1dt`） | 2.25e-4 | 4.69e-4 | 1.90e-4 | 3.41e-4 |

**yfch 比 cyber 高整整一个量级，而 yfch 在两个 run 里都活到了最后、且是 flash 上通过率涨得最多的数据集（+34.99pp）。** 所以"`pg_tis_clipfrac` 高"这个特征本身并不能解释为什么移除的是 cyber 而不是 yfch。四条 `pg_tis_clipfrac_*` 子桶（`pos_high/pos_low/neg_high/neg_low`）的排序完全一样：yfch 第 1、cyber 第 2。

### 7.3 找不到的三类证据

- **不存在"cyber 在崩"**：通过率在 pro 的 14 步里从 56.39% 升到 64.17%，斜率 +1.03 pp/步（p=0.0086）；熵从 0.456 到 0.492，正常抬升；`clip_ratio` 没有异常。
- **`actor/*/ppo_kl` 和 `actor/*/pg_clipfrac` 在数据集层恒等于 0**（pro 542 个值、flash 690 个值全部为 0），这两族**不能用于任何推断**，也就不可能承载"坏模式"。
- **cyber 唯一真正独特的量是"负奖励尾部"**，而 yfch 在同一维度上更重（pro 的 `< −0.3` 占比 35.7% vs cyber 14.3%）。**所以连这条也不能单独指认 cyber。**

**结论一句话**：数据能支持"cyber 在被移除前有一个偏重的负奖励尾部、并且是全期第 2 高的 TIS 裁剪率、全期第 2 长的轨迹"，但**支持不了"cyber 有问题而别的数据集没问题"**。公告所依据的"rollout 日志里的坏模式"在这批标量指标里不可见。

## 八、数据集之间的领先 / 滞后（问题 6）

**结论**：**没有可靠的先后顺序。** 全部 300 对数据集在 lag = −4…+4 上的平均差分互相关绝对值都 ≤0.022；净领先分最高最低只差 7~9（对手 24 个），符号检验 p 最小 0.064。

### 8.1 证据

| 度量 | pro | flash |
|---|---|---|
| 平均互相关曲线（lag = −4…+4，每格 297~300 对） | 全部 \|ρ\| ≤ 0.022 | 全部 \|ρ\| ≤ 0.014 |
| 净领先分极差（每对判一次胜负） | 7（16 胜 vs 9 胜） | 9（17 胜 vs 8 胜） |
| 领先分最高者的符号检验 p（对手 24 个） | 0.152（`code/dataset-zg6q`） | 0.064（`code/dataset-obg8`） |
| 单对最大 \|lag 不对称\| | 1.216（ta4j vs gtav，gtav 含哨兵 0） | 0.886（053e vs gtav） |

**平均互相关曲线在 lag 0 都不是峰值**（pro 的 lag 0 是 −0.011、lag −4 是 +0.022），这本身就是"没有共同节拍"的直接证据。

### 8.2 唯一像"顺序"的东西，两个 run 不一致

| 假设 | pro | flash |
|---|---|---|
| 期初越难 → 突破越晚（突破步 = 3 步滑动均值首次超过首值 +2pp 的步） | ρ=0.069，n=19，p=0.78 | **ρ=0.434，n=23，p=0.039**（临界 0.413） |
| 期初越难 → 最终涨幅越大 | ρ=−0.360，n=23，p=0.092 | ρ=−0.375，n=23，p=0.078 |

flash 里"难的后突破"过了 0.05 线，pro 里完全没有；而"难的涨更多"在两个 run 上都只是 p≈0.08~0.09 的边际。**两个 run 不一致 + 都是边际，我不把它当成课程（curriculum）结构的证据**，更可能是"通过率有天花板 + 期初低的数据集统计噪声大"这两件事的合成。

### 8.3 反过来，真正稳健的是"哪个数据集涨得多"本身可复现

| 检验 | 结果 |
|---|---|
| 25 个数据集在两个 run 上的 Δpp 秩相关 | **ρ=0.582，n=25，p=0.0023**（临界 0.396） |
| 两个 run 共同的大涨家 | m1dt（+14.10 / +17.78）、x7wh（+6.27 / +15.36）、jzd3（+15.36 / +13.00）、ve5o（+8.36 / +13.37）、zg6q（+3.35 / +8.31） |
| 两个 run 共同的不涨家 | bvg7（−2.84 / −1.41）、v7yx（−9.17 / −4.50）、5610（−1.60 / −3.06）、8kb6（+2.72 / −4.16） |

**这是本文里最强的"异质性真实存在"证据**：连训两个不同的模型（pro / flash），数据集层的强弱排序是可复现的。它同时反过来支持 §五的结论——如果配比挪动是主因，两个 run 的排序不会这么一致。

## 九、动态采样的行为（问题 7）

**结论**：① 中文解读里那条"held ≈ 本步受理数 + 上一步 carryover"**成立**，在 pro 的 74.7%、flash 的 86.8% 的（数据集 × 步）上成立；断链步**全部**是"重启后的第一个上报步"（外加链首的第 1~3 步）。② "采样器把流量从已经学会的和完全不会的数据集上撤走"这个设计意图，**在数据里检不出来**：倒 U 形回归在混合 OLS、数据集固定效应、非参分箱三种做法下都不显著。

### 9.1 held 恒等式的验证

检验式：`dynsam/<cat>/dataset-<id>/num_accepted/held(t) = 同族/step(t) + 同族/carryover(t−1)`，判定阈值为相对误差 ≤5%。

| run | 成立的（数据集 × 步） | 占比 | 断链步 | 断链步的特征 |
|---|---|---|---|---|
| pro | 422 / 565 | **74.69%** | 2, 3, 11, **15, 17, 23** | 第 3、11、15、17、23 步都是"重启后的第一个上报步"；第 2 步是链首 |
| flash | 629 / 725 | **86.76%** | 3, **16, 25, 28** | 第 16 步是重跑步，25、28 是重启后首步；第 3 步是链首 |

断链不是零散的：在每一个断链步上，**几乎所有 24~25 个数据集同时断**（例如 pro 第 11 步 25/25、第 15 步 24/24、第 17 步 24/24）。这说明它是**步级事件**（结转链被重置），不是数据集级的噪声。中文解读里"重启后的那一步这个关系不成立、结转链会被重置"得到确认，并且可以补充两点：**（a）链首几步也会断（pro 第 2 步、flash 第 3 步）；（b）pro 的断链步比"重启步"多一个第 2 步。**

### 9.2 采样器是不是在"撤已学会的、撤完全不会的"

三种检验，全部否掉：

| 检验 | pro | flash |
|---|---|---|
| 数据集份额变化 vs 期初通过率（Spearman） | ρ=0.039，n=23，p=0.86 | ρ=0.065，n=23，p=0.77 |
| 数据集份额变化 vs 末期通过率 | ρ=−0.118，p=0.60 | ρ=0.042，p=0.85 |
| 数据集份额变化 vs 该数据集通过率变化 | ρ=−0.059，p=0.79 | ρ=0.062，p=0.78 |
| 倒 U 回归（混合 OLS，n=519/667）：二次项 | −0.737，p=0.81 | +0.400，p=0.89 |
| 倒 U 回归：一次项 | +1.021，p=0.79 | +0.355，p=0.92 |
| 同上，加数据集固定效应：二次项 | −3.398，p=0.60 | +4.817，p=0.35 |
| 中间带 p∈[0.35,0.75) vs 两端的份额变化（Welch t） | 差 −0.091pp，p=0.66 | 差 −0.158pp，p=0.37 |

非参分箱（每箱内"下一期份额变化"的均值，单位 pp）：

| 滞后一期通过率 | pro | flash |
|---|---|---|
| [0, 0.35) | −0.252 | +0.028 |
| [0.35, 0.45) | +0.018 | −0.147 |
| [0.45, 0.55) | −0.002 | −0.019 |
| [0.55, 0.65) | +0.012 | −0.051 |
| [0.65, 1.01) | +0.016 | **+0.280** |

倒 U 应该看到"两端为负、中间为正"。pro 只在最低箱看到负值（−0.252）、其余全平；flash 恰恰相反，**流量明显流向最容易的那一箱（+0.280）**。**两个 run 的形状互不一致，且都不符合设计意图。**

### 9.3 那个看起来像"撤已学会的"个案

pro 里 `code/dataset-m1dt` 的份额掉了 3.09pp（最大跌幅），而它同期通过率涨了 14.10pp（最大涨幅之一）；flash 里 `code/dataset-x7wh`（−2.55pp，通过率 +15.36pp）和 `m1dt`（−2.35pp，+17.78pp）也是同一个样子。**只看这两三个点，很像"学会了就被撤流量"。** 但把它们放进全部 23 个数据集做秩相关只有 ρ=−0.06（p=0.79）；同时 flash 最大的份额增长（+3.18pp）恰恰给了通过率涨得最多的 `yfch`（+34.99pp），方向完全相反。**所以我不认为这是规律，只能说是个案。**

> **可迁移概念 4｜动态采样的样本池收缩（pool shrinkage）与"流量份额"这个口径**
> 定义：动态采样按某种难度信号决定每一步从每个数据源"受理"多少题进训练 batch。它的设计意图通常是"把算力从已经学会的（再采样没有梯度）和完全不会的（全是负样本、噪声大）两端，收向中间难度"。检验它的正确口径不是看绝对受理数（各数据源量级差一到两个数量级，而且总池子本身每步波动 2.9 倍），而是看**归一化份额的变化**，并且要用"滞后一期的难度"去解释"当期的份额变化"。
> 本文体现：份额变化的量级只有 ±0.1pp/步，而通过率水平对它的解释力在四种做法下都不显著（p 0.35~0.92）。同时文档明确警告数据集层的受理数之和比 `dynsam/agentic/num_accepted/step` 系统性高 10%~18%，两层口径不同。
> 可迁移规则：**判断"调度器是否按某个信号分配资源"，要用份额而不是绝对量、要滞后一期避免同期内生性、并且一定要加实体固定效应**（否则"大池子一直大"会吃掉全部解释力）。若三种口径都不显著，就老老实实写"数据不支持这个设计意图"，不要用两个个例讲故事。

## 十、不确定、被推翻、看不对的地方

### 10.1 被这次分析修正/推翻的既有说法

| 既有说法 | 这次的结果 |
|---|---|
| `notes/09`：gtav/ol8x 的精确 0"可能是未上报哨兵" | **确认是哨兵，并进一步定位：全部落在"第 1 步 ∪ 重启受影响步"上**（pro 7/7、flash 5/5），且同期 `critic` score 正常。不是零散漏报，是重启耦合的成片缺报 |
| `metrics.json`：held 恒等式"重启后的那一步会断，pro 有 3 处、flash 有 3 处" | 断链步是 pro **6** 处（2,3,11,15,17,23）、flash **4** 处（3,16,25,28）；多出来的 pro 第 2 步不是重启步，是链首。重启受影响步本身是 pro 5 个（3,11,15,17,23）、flash 3 个（16,25,28） |
| `notes/09`：pro 的 cyber"在第 15 步之后停止上报" | 精确说是**第 14 步是最后上报步，第 15 步起全空**，42 个 cyber 指标无一例外 |
| `notes/09` 用"等权类别均值"描述总体长度 | 本文用"按 `num_accepted/step` 加权的数据集均值"，口径不同（本文 pro 末值 123136 而非 114676）。两种都对，但不能混用；构成效应必须在加权口径下才定义得清楚 |

### 10.2 明确不确定的

1. **`visual/dataset-053e` 做不了弹性分析**：它没有任何生成长度或总长度指标，只有 prompt 长度。这是上报口径缺口，不是分析选择。
2. **`visual/dataset-gtav` 的 `critic/.../score/mean` 和它的平均通过率差了 27~30pp**（pro 平均差 30.09pp、flash 27.45pp），是全部数据集里最大的（第二大的 ol8x 只有 8.2pp / 2.9pp，其余都 ≤2pp）。也就是说 gtav 的"奖励分"和"通过率"是两回事。**我没能解释这个差异**——可能是 gtav 的评分带部分分、也可能是两个指标覆盖的题不是同一批。涉及 gtav 的任何"成绩"结论我都不下。
3. **`chat/dataset-eup7`@pro 的差分弹性 −27.34 pp/万 token（p=0.004）我标为低置信**：它的长度只有 0.9k~8.3k，1 万 token 的外推幅度是观测范围的 1.2 倍以上。
4. **`code/dataset-x7wh`@pro 的水平弹性是"伪显著"**：去掉一个高杠杆点后 p 从 0.030 变成 0.086。这类结论在 n=24 的回归里很容易出现，我把它单列出来当警告。
5. **"负奖励尾部"是否是 cyber 的"坏模式"**：数据上 cyber 的 `< −0.5` 步占比在两个 run 都排第 1，但 yfch 在 `< −0.3` 上更重、`pg_tis_clipfrac` 更是高一个量级却活到最后。**我倾向于认为"坏模式"指的是轨迹内容层面（比如绕开测试、越权操作之类），这批标量指标看不到**，但我无法证明。

### 10.3 看不懂 / 对不上

1. **`train/passrate/passrate_0_ratio` 与 `passrate_1_ratio` 我不知道在数什么。** 109 条中文解读里没有这两条。pro 的 `passrate_0_ratio` 从 0.92% 单调升到 6.19%（第 14 步），**在第 15 步掉回 1.12%** 再重新爬；flash 从 0.91% 单调升到 8.30%，中途重启**没有**重置。它和同名的 `dynsam/passrate/zero`（13%~17%、几乎不动）完全不是一个量级。pro 的"第 15 步重置"和 flash 的"不重置"互相矛盾，我给出的两种猜测（累积量 / 滑动窗口）都被其中一个 run 否掉了，所以不猜了。
2. **看板全局 `train/passrate/avg_passrate` 和我们用数据集层加权重构的值不是同一个东西**。中位相对差只有 0.73%（pro）/0.90%（flash），但**最大到 7.45%（pro 第 15 步）/5.06%（flash 第 3 步），而且最大差就出现在重启步上**。原因应该是看板全局里含了一个**没有在数据集层拆出来的 agentic 池**（`dynsam/agentic/num_accepted/step` 的量级约 1300~2500，和 25 个数据集之和同量级）。用恒等式反解这个池子的通过率，pro 从 51.23% 升到 58.46%（+7.23pp）、flash 从 47.76% 升到 59.37%（+11.62pp）——**比可见数据集层的涨幅（+3.54 / +9.15pp）还快**。这个反解依赖"两层权重可直接相加"的假设，而 `metrics.json` 明确说两层口径不同（数据集层之和比 agentic 层系统性高 10%~18%），所以**这个反解只能当解释性线索，不能当数字用**。
3. **`env/possible_leak` 在 pro 的第 19~22 步变成 1，其余全部为 0**（flash 全程 0）。这是一个计数不是一个比例，我不知道它数的是什么、也不知道为什么只在 pro 的最后阶段出现。它出现在 cyber 被移除**之后**，所以和 cyber 无关，但可能和公告里的"坏模式"是同一类东西。留给下一轮。

## 十一、术语速查表

| 术语 | 一句话人话定义 |
|---|---|
| `train/passrate/avg_passrate/<cat>/dataset-<id>` | 该数据集这一步进入训练的那批题，逐题 16 次采样的成功比例，再跨题取平均（= 这个数据集的"平均分"） |
| `dynsam/<cat>/dataset-<id>/num_accepted/step` | 采样器这一步从该数据集"受理"、真正送进训练 batch 的题数（= 流量） |
| `.../num_accepted/held` | 该数据集当前留在题池里、还没被消耗掉的题数 |
| `.../num_accepted/carryover` | 上一步留在池子里、结转到这一步的题数 |
| `dynsam/avg@n` | 首页主指标，逐题"成功次数/16"的跨题平均；不等于"做对的题占比" |
| `dynsam/passrate/zero` | 16 次尝试**一次都没成功**的题占比（难度下限）；全局有，数据集层没有 |
| `ctx_response_length/mean` | 一条轨迹平均生成了多少 token（单位 token） |
| `actor/.../entropy_loss` | 策略熵；越低说明输出越确定（在数据集层是这一步该数据集的策略熵） |
| `pg_tis_clipfrac` | 截断重要性采样（truncated importance sampling）里被裁剪的样本比例；越大说明训练器和推理引擎对同一批 token 的判断分歧越大（离线/过期数据越多） |
| `critic/.../score/min` | 这一步该数据集**最差**那条轨迹拿到的分数，用来量负奖励尾部 |
| 辛普森悖论 / 构成效应 | 总体均值 = 分组均值 × 权重；权重一变，总体可以朝着与所有分组都相反的方向动 |
| shift-share 三项分解 | `ΔA = Σs₀Δp + ΣΔs·p₀ + ΣΔs·Δp`，把总变化精确拆成"自己变好 / 配比挪动 / 交互" |
| 哨兵值（sentinel） | 用 0 或某个固定值代替"这一项没上报"，不是真实测量值 |
| 高杠杆点（leverage） | 自变量方向上离群太远的单个观测，能让小样本回归的斜率显著而虚假 |
