# 指标空间与潜在因子：那 2000 个指标其实等于几条曲线

> 材料身份：**我方实测**。数据来自本地只读遥测 `data/store/`，全部数字由脚本 `src/factor_report.ts` 从原始 JSON 现算，脚本里没有硬编码任何结论数字；运行 `bun src/factor_report.ts`（项目根目录）可一键复现，同时写出 `analysis/zh-CN/numbers/A3-factor-numbers.json`。
> 数据截止：**pro 第 24 步（2026-09-19 08:58:10Z 快照）、flash 第 30 步（2026-09-19 03:07:03Z 快照，已结束）**。
> 样本量极小：pro 只有 24 个时间点、flash 30 个。相关矩阵在 1389 / 1465 个指标上估计，属于"变量比样本多两个数量级"的高维小样本，特征值和载荷都有很大抽样噪声，第三节的稳健性检验是本报告不可跳过的部分。
> 与已有材料的关系：`notes/09-生成长度相关性分析.md` 已经从"长度与谁相关"的角度做过水平相关与一阶差分；本报告做的是**指标空间自身的结构**（维数、潜在因子、冗余、阶段、偏相关、跨 run 对齐），只在第 5 节与它有一处必要的交集，已注明。

---

## 一、摘要

1. **这块看板的有效自由度是 11～13，不是 2000。** 把 pro 的 1389 个可分析指标（覆盖率 ≥80% 且非常数）各自标准化后做相关矩阵，参与率（participation ratio，下面的术语表有解释）为 **11.21**；flash 为 **12.99**（截到同样的 24 步后是 **12.12**）。解释 80% 方差 pro 需要 **14** 个主成分、flash 需要 **17**（截 24 步后也是 14），90% 分别需要 **18 / 22** 个。**一句话：约 2000 个指标大致相当于 12 条独立曲线**，其余是这些曲线的切片副本和噪声。

2. **最少 15 个指标就能复现看板 83% 的总方差，20 个能到 95%。** 用"方差贪心前向选择"（每一步挑让剩余方差掉得最多的那个指标）在 pro 全量 1389 个指标上选：第 5 / 10 / 15 / 20 个的累计解释方差是 **51.1% / 69.2% / 83.5% / 94.8%**。只用 285 个"根级聚合指标"（不带数据集 id、不带新鲜度桶号、不带 harness 字母的那一层）结果几乎一样（**51.0% / 68.7% / 82.8% / 94.5%**）。flash 对应是 47.7% / 62.5% / 74.6% / 85.0%。

3. **前两个主成分占了三分之一以上的方差，而且两条 run 能对上。** pro 的 PC1 占 **21.0%**、PC2 占 **14.6%**；flash 是 **18.6% / 14.8%**。按载荷向量余弦配对，pro PC1↔flash PC1 **|cos|=0.799**、PC2↔PC2 **0.793**；截到同样 24 步是 **0.759 / 0.696**。到 PC3 掉到 **0.449**（截 24 步后 0.248）、PC4 只有 **0.269**。**两条 run 共享的只有两个宏观因子，第三个开始就是各自的运维细节。**

4. **指标"多"主要是命名层面的复制，不是信号层面的冗余。** 1389 个可分析指标里有 **1072 个（77.2%）**属于"只差切片段"的副本组（同一个指标按数据集、按 harness 字母、按新鲜度桶拆开；flash 是 1159/1465 = 79.1%）。但统计上并不高度冗余：任意两个指标的 |ρ| 中位数只有 **0.187**（flash 0.167），|ρ|≥0.9 的指标对只占 **0.41%**。另有 **294 个指标是常数**（占原始 1944 的 15.1%），其中 **224 个恒等于 0**，几乎全是 `pg_clipfrac` / `ppo_kl` 家族。

5. **长度与成绩的相关是共同时间趋势，数据陈旧度与全局 KL 的相关不是。** 控制步序号后（残差法）：`ctx_response_length/mean`（本步平均生成长度）与 `dynsam/avg@n`（平均通过率主指标）从 **0.766 → −0.013**（pro）、**0.920 → −0.140**（flash）；而 `partial/avg_staleness`（本步数据的平均陈旧度）与 `train_infer_diff/new_infer/kl`（训练器与推理引擎的数值分歧）从 **0.923 → 0.941**（pro）、**0.866 → 0.892**（flash），**没有缩水**。同样反直觉的是 `actor/entropy_loss`（策略熵损失）与 `avg@n` 控制趋势后**变号**：0.578 → **−0.620**（pro）、0.889 → **−0.395**（flash）。

6. **"阶段"绝大多数是运维事件，不是模型状态变了。** 在 PC1-3 坐标上做变点检测，pro 与 flash 的最大变点都落在**第 15 步**（pro 的重启正好在第 15 步墙钟、差 0 小时），而且位移在 3 步内**退回原水平**（回退比 pro **0.97**、flash **0.93**）——这是重启把队列冲掉的瞬时冲击，不是台阶。去趋势之后剩下的候选变点，也都能在 0～4 小时内对上重启或版本切换（pro 第 23 步：位移 2.56，最近重启同一步、最近版本切换差 1.09 小时，动的是 `env/active` 与长度截断率，即数据集组成）。

## 二、方法与数据来源

| 项目 | 内容 |
|---|---|
| 数据文件 | `data/store/runs/pro/series.json`（1944 指标 × 24 步）、`runs/flash/series.json`（1974 × 30）、两人的 `axis.json` / `status.json` / `tags.json`、`data/store/notices.json`、`content/metrics.json`（109 条中文逐指标解读，用来给指标族起名） |
| 采集时刻 | pro 快照 2026-09-19 08:58:10Z（第 24 步完成后 3965 秒，仍在 rollout 中）；flash 快照 2026-09-19 03:07:03Z（第 30 步后，run 已 end） |
| 分析单位 | **指标 × 步** 矩阵；每一列（一个指标）先自己 z-score（减均值、除总体标准差），再做相关矩阵与特征分解。所以恒等式在绝对值层面成立、在标准化之后不一定成立，第五节专门处理 |
| 缺失口径 | 原始单元格 7.86%（pro）/ 7.43%（flash）是 null。**主口径：覆盖率 ≥80%**（pro 需 ≥20/24 步非空、flash 需 ≥24/30），通过后做**线性插值**（两端取最近已知值），再 z-score。→ pro 1389 个、flash 1465 个进入分析 |
| 剔除 | 覆盖率不足：pro 261 / flash 232；**零方差（常数）**：pro 294 / flash 277（零方差无法标准化，必须剔除，不是"数据缺失"） |
| 特征分解 | 自写 Jacobi 循环旋转（脚本自检 `max|Av−λv| = 9.3e-15`） |
| 聚类 | 距离 = `1 − |ρ|`，平均连接（UPGMA）。脚本自检：自写的"最近邻缓存贪心"与朴素 O(n³) 平均连接在 n=60 随机点上 **ARI = 1.0000**（最初用最近邻链 NNC，自检发现它对 UPGMA 会收敛到局部互近邻对、不是全局最近对，已换掉） |
| 变点 | 主成分坐标（PC1-3，各自标准化成单位方差）上做贪心二分分割，接受条件 `RSS 降幅 > dim·ln(N)·σ²`（BIC 风格）；同时给出**无惩罚**的逐位置统计量排序，避免结论依赖惩罚强度 |
| 偏相关 | 控制变量 = 步序号（0-based）。两条序列各自对步序号做最小二乘回归，取残差，再算 Pearson。这是"去掉共同线性趋势后还剩多少关系"的标准做法 |
| 复算 | `bun src/factor_report.ts`，约 5 秒，输出全部数字并写 `A3-factor-numbers.json` |

**指标族的定义**（本报告全篇用它做归并）：把指标名里的 `dataset-xxxx` 换成 `dataset-<id>`、`partial/3/` 换成 `partial/<k>/`、`harness-A` 换成 `harness-<x>`、类别段（agentic/chat/code/visual/general/cyber）换成 `<cat>` 之后得到的模板。例如 `ctx_response_length/code/dataset-bvg7/mean` 的族是 `ctx_response_length/<cat>/dataset-<id>/mean`。

## 三、先剔除"机械结构"：哪些东西必然占据维度，不算发现

> **结论**：这块看板上确有三类机械关系，但**在标准化之后，它们并没有各自占据一个独立主成分**；它们表现为"同一个信号的两个副本"。

**大白话**：看板上有几个数是从别的数算出来的，看它们等于在重复看同一个数。但因为我按"每个指标各自标准化"来分析，这些恒等式在标准化之后就不再精确成立，所以它们不会像在原始尺度上那样压倒一切。把它们剔掉再看，谱形状几乎不动。

**证据表**

| 机械关系 | 复算结果（pro / flash） | 处理 |
|---|---|---|
| `ctx_total_length/*/mean ≈ ctx_prompt_length/*/mean + ctx_response_length/*/mean`（总上下文长度 = 提示词长度 + 生成长度） | 22 组，**最大残差 0.920 / 0.960 token**（相对几十万 token 的均值可忽略） | 剔除 `ctx_total_length/*`（102 个）后再看谱 |
| `Σ_k partial/<k>/frac = 1`（8 个新鲜度桶的 token 占比之和恒为 1） | 最大偏差 **1.00e-6 / 1.12e-6** | 作为冗余证据保留，剔除法见下 |
| 全局 `train_infer_diff/new_infer/kl = Σ_k partial/<k>/frac × partial/<k>/…/kl` | 最大绝对偏差 **1.19e-5 / 1.14e-5**（相对 0.148% / 0.151%） | 同上 |
| `partial/<k>/n_tokens = frac × 本步 token 数` | 由 frac 求和恒等式与 `perf/total_num_tokens` 共同决定 | 一并剔除 |

**剔掉之后谱几乎没变**：pro 从 d=1389 降到 d=1294，PC1 从 21.0% 变 **20.5%**，n80 仍是 14，参与率从 11.21 变 **11.34**；flash 从 1465 降到 1361，PC1 从 18.6% 变 **17.7%**，n80 仍是 17，PR 13.0 → 13.16。**换句话说，没有哪个主成分是恒等式"造"出来的。**

**但恒等式家族在标准化空间里仍然是一个双胞胎**：`ctx_total_length/<cat>/mean` 与 `ctx_response_length/<cat>/mean` 的平均 |ρ| 是 **0.947（pro）/ 0.970（flash）**，而它与 `ctx_prompt_length/<cat>/mean` 只有 **0.276 / 0.172**。原因很直白：`ctx_prompt_length/mean` 全期只在 3964～4489 token 之间（变异系数 **2.85%**），而响应长度在 65100～114700 之间（变异系数 **14.0%**）。**总长度这条线实际上就是在画生成长度**，提示词长度几乎没有信息量。看板上同时挂 `ctx_total_length` 和 `ctx_response_length` 是重复的，挂 `ctx_prompt_length` 是近乎常数的。

另外两条"不是恒等式但接近"的：`training/global_step` 就是 1..24 的步号本身（均值 12.5、标准差 6.922，完美共线）；`dynsam/num_target` 全期恒等于 1568（零方差），所以它与其他指标的相关是未定义的（脚本里报 NaN）。真正"随时间单调走"的指标很少：与步序号 |corr|≥0.95 的只有 **13 个（占 0.9%，pro）/ 27 个（1.8%，flash）**。

## 四、有效维度：特征值与参与率

> **结论**：pro 的有效自由度 **11.21**、flash **12.99**（同为 24 步时 12.12）。前 5 个成分解释 pro 的 53.1%、flash 的 49.6%；要到 80% 需要 14（pro）/ 17（flash）个成分。

**大白话**：主成分分析是把很多条曲线重新组合成"互相不相关的新曲线"，第一个新曲线解释最多方差，依次递减。如果 2000 个指标真的各说各话，方差会平摊到很多成分上；如果它们其实在重复说几件事，头几个成分就会吃掉大部分方差。"参与率"是把整条特征值谱压缩成一个数：方差越集中在少数成分上，它越小。它回答的是"等效独立信号数"。

**证据表**

| 量 | pro（d=1389, N=24） | flash（d=1465, N=30） | flash 截到 24 步 |
|---|---|---|---|
| PC1 / PC2 / PC3 方差占比 | 21.0% / 14.6% / 7.0% | 18.6% / 14.8% / 6.4% | 20.2% / 12.9% / 7.3% |
| 前 5 成分累计 | 53.1% | 49.6% | 51.0% |
| 解释 80% / 90% / 95% 需要的成分数 | 14 / 18 / 20 | 17 / 22 / 26 | 14 / 19 / — |
| 参与率 (Σλ)²/Σλ² | **11.21** | **12.99** | **12.12** |
| 剔除机械家族后 | 11.34（d=1294） | 13.16（d=1361） | — |
| PC1 得分与步序号 \|corr\| | 0.822 | 0.888 | — |
| 逐指标去线性趋势后 PC1 / PC2 | 18.9% / 10.3% | 17.6% / 9.3% | — |
| 纯噪声上边缘 (1+√(d/(N−1)))² | 76.9 | 65.7 | — |
| 超过噪声上边缘的成分数 | 23（=全部非零） | 30（=全部非零） | 23 |

两个必须说清的读数陷阱：

- **n80 不能跨 run 直接比。** flash 时间点更多（30 vs 24），能分辨的成分上限本来就更高，所以它 n80=17 有一部分是"点更多"而不是"更复杂"。把 flash 截到前 24 步后 n80 也是 **14**，与 pro 持平；参与率 12.12 vs 11.18，差距从 1.78 缩到 0.93。
- **"纯噪声上边缘"这个对照在这份数据上不构成筛选器。** 它给出的是"如果所有指标互不相关，特征值最大能到多少"（pro 76.9）。实际最小的非零特征值也远高于它，所以 23 个成分**全部**都有结构——但这个"结构"里包含共同趋势和运维冲击，不等于 23 个独立的科学发现。有效维度应以参与率/80% 口径为准。

**直观结论：2000 个指标 ≈ 12 条独立曲线。** 其中前 2 条（合计 ~35%）是宏观因子，第 3～14 条是各子系统各自的信号，剩下的是同一条曲线的切片副本与小样本噪声。

## 五、潜在因子：前 5 个主成分在讲什么

> **结论**：PC1 是"训练进展的规模与长度轴"（与步序号共线度 0.82/0.89）；PC2 是"数据新鲜度与采样流量配比"；PC3 以后是判分/选择流程细节和奖励下尾，且两条 run 到 PC3 就对不上了。

**大白话**：每个主成分是许多指标的一个加权组合，权重（载荷）大的指标说明这个成分主要在画它们。要注意载荷本身很"平"——最大载荷约 0.05～0.09，而完全均匀时是 1/√1389 ≈ 0.027——所以没有任何一个指标能单独代表一个成分。为了避免"哪个族人多就哪个族上榜"的错觉，我同时报了**富集倍数**：某族在这个成分里占的载荷份额 ÷ 它自己占的指标数份额，大于 1 才叫超额代表。

### PC1（pro 21.0% / flash 18.6%）：进展与长度轴

- 载荷最大的一批（pro）：`+0.054 train/adv_neg_sum_pre_penalty`、`+0.054 train/adv_neg_sum_post_penalty`、`−0.054 perf/total_num_tokens`、`−0.054 ctx_total_length/mean`、`−0.054 ctx_response_length/mean`、`−0.050 ctx_total_length/general/dataset-trla/max`、`−0.050 timing_s/trainer_ops`（本步训练器耗时）。
- flash 的同一成分符号相反（配对余弦 **−0.799**）：`+0.059 train/adv_pos_sum_pre_penalty`、`+0.059 perf/total_num_tokens`、`+0.059 ctx_total_length/mean`、`+0.058 timing_s/trainer_ops`、`−0.057 train/adv_neg_sum_*`。
- 富集倍数（pro）：`ctx_response_length/<cat>/dataset-<id>/mean` **×2.3**、`actor/<cat>/…/pg_tis_clipfrac` **×2.3**、`ctx_total_length/<cat>/dataset-<id>/mean` ×2.2；flash：`ctx_response_length/…/mean` **×3.3**、`ctx_total_length/…/mean` **×3.2**、`actor/<cat>/…/entropy_loss` ×2.0。
- 支持命名"进展与长度轴"的证据：得分与步序号 |corr| 0.822（pro）/ 0.888（flash）；载荷最大项同时包含 token 总量、上下文长度、训练器耗时、优势总和这些"随训练放大"的量。**它是趋势，但不是纯时间轴**（0.82 不是 1.0），里面还混着长度与裁剪结构。

### PC2（pro 14.6% / flash 14.8%）：数据新鲜度与采样流量配比

- pro：`+0.066 dynsam/visual/dataset-gtav/num_accepted/step`（采样器本步受理题数）、`+0.066 train/trace/files`、`+0.065 train/trace/writer_seconds_sum`、`+0.064 partial/code/dataset-zg6q/0/n_tokens`（最新鲜那一桶的 token 数）、`+0.061 penalty/…/harness-A/groups_judged`。
- flash：`+0.065 dynsam/num_measurable`、`−0.062 env/general/dataset-trla/active`、`+0.061 partial/0/n_tokens`、`+0.061 penalty/…/groups_total`。
- 富集倍数：pro `partial/<cat>/…/0/n_tokens` **×4.1**、`dynsam/<cat>/…/num_accepted/step` **×3.2**、`partial/<cat>/…/avg_staleness` ×2.7、`partial/<cat>/…/0/frac` ×2.7；flash 同族 ×4.5 / ×4.3 / ×4.1 / ×4.0。**两条 run 在这个成分上高度一致**（配对余弦 0.793，截 24 步 0.696），名字可以放心起。
- 得分与步序号 |corr| 只有 0.477（pro）/ 0.328（flash），所以它是"非趋势"的真实波动轴。

### PC3（pro 7.0% / flash 6.4%）：判分与选择流程的配额/冲突

- pro：`+0.082 train/verdicts/carried`、`+0.075 penalty/stage_credit_group/harness/harness-D/select_rank_invalid`、`+0.071 …/select_tier_mismatch`、`+0.065 …/select_r2_flagged`、`+0.065 critic/code/dataset-4onq/score/mean`、`+0.062 penalty/…/select_v4/time_total_sec_mean`（判分各阶段耗时），以及 `−0.063 partial/0/train_infer_diff/new_infer/F(tau=10)`。
- flash：`+0.075 penalty/…/harness-A/select_renorm_k_mean`、`−0.069 penalty/…/select_v4/select_score_S_mean`、`+0.069 …/select_rank_score_conflict`、`−0.069 …/select_tier_share_T1`。
- 配对数余弦只有 **0.449**（截 24 步 **0.248**）：两条 run 的第三因子已经在讲**不同的判分细节**（pro 讲"选择失败/等级不匹配"，flash 讲"分数重归一化/档位占比"）。命名对 pro 成立，对 flash 只能叫"判分配额轴"。

### PC4（pro 5.7% / flash 5.6%）：判分成功率的正反面

pro：`+0.079 penalty/…/select_v4_nogold/end2end_success_rate`、`+0.078 …/pass1_success_rate`、`+0.077 …/select_hack_attempt_rate` 对上 `−0.078 penalty/…/harness-D/groups_failed_select`、`−0.075 penalty/…/groups_failed_select`。也就是"判分成功"与"选择阶段丢组"是同一个轴的两端。富集倍数：`dynsam/…/num_accepted/held` ×2.0（持有的题）、`select_v4_nogold/<metric>` ×1.9。配对数余弦 0.269。

### PC5（pro 4.9% / flash 4.2%）：长度截断与奖励下尾

pro：`+0.093 critic/code/dataset-v7yx/advantages/min`、`+0.093 …/returns/min`、`+0.091 …/rewards/min`、`+0.091 …/score/min`（同一个数据集的四个"最小值"指标一起动，说明它们本身就是一个信号的四份副本），配 `−0.089 ctx_prompt_length/general/dataset-5610/max`、`−0.089 ctx_total_length/code/dataset-dnpn/clip_ratio`（截断率）。富集倍数：`ctx_total_length/<cat>/…/clip_ratio` ×3.5、`critic/<cat>/…/*/min` ×2.4～2.6。flash 的 PC5 则是 `partial/<cat>/…/1/frac`（陈旧度第 1 桶占比）与采样器结转量，配对数余弦只有 0.101～0.113，**基本是各自 run 特有的东西**。

## 六、冗余结构：一个巨型背景 + 若干紧密小簇

> **结论**：聚类在最高层几乎分不开——pro 的一个簇装了 847/1389（去趋势后），原始相关下更是 1069/1389（77%），且最高层合并距离都在 0.7 以上。**"8～15 个簇"这个切法是可用的阅读工具，但不是数据里天然存在的分块**（留一步重跑的 ARI 中位数只有 0.53/0.55）。

**大白话**：层次聚类是把最像的两个指标先并起来，再并次像的。如果数据里真有几"家族"，最后几次合并会在很低的距离上发生，形成清晰的分块。这块看板不是这样：绝大多数指标彼此都只是弱正相关（|ρ| 中位数 0.19），最后所有的东西被一根"背景相关"串成一个大团，小簇挂在大团外面。

|---|---|---|

### 6.1 哪些族其实是同一个信号的不同副本

把键只差"切片段"的指标归成一组（同一指标 × 数据集 × harness 字母 × 新鲜度桶），得到 **101 组（pro，覆盖 1072 个指标 = 77.2%）/ 103 组（flash，1159 个 = 79.1%）**。组内平均 |ρ| 的中位数只有 **0.260（pro）/ 0.282（flash）**——**名字是副本，数值不一定是副本**。

## 七、步的阶段性：这些"阶段"是谁造成的

> **结论**：能找到的阶段边界几乎都能对上运维事件；**能对上重启的变点，位移在 3 步内就退回去（回退比 ≈1），这是"重启把队列冲掉"的瞬时冲击；去趋势后剩下的少数持续台阶，对应的是数据集增删和版本切换。**

**大白话**：两种东西会让曲线在某一步"变样"：模型变了（学习到了新东西，台阶会保持住），或者运维把管线重置了（重启、换版本、增删数据集，曲线会跳一下然后回到原来的走势）。区分办法就是看跳完之后回不回来，以及跳的位置和重启/换版本的时间对不对得上。

**pro 的证据**

**"重启附近位移更大"这条只在 flash 成立，pro 反过来**：把去趋势位置统计量按"是否在重启步及其后 2 步内"分组，flash 是重启附近中位 **5.92**（n=9）对其它 **2.36**（n=18），pro 是 **2.42**（n=12）对 **3.44**（n=9）。pro 有 11 次重启但只落在 5 个步边界上（第 3、11、15、17、23 步），重启很密集，反而不构成"更特殊的步"。

1. **最大变点落在重启的那一步，且位移在 3 步内退回原水平**（回退比 0.97 / 0.93）。模型能力提升不会 3 步内退货。
2. **去趋势后的持续台阶，动的是"环境/数据"类的量**（`env/active`、`env/total_error`、长度截断率、`partial` 桶占比），不是 `critic/rewards/mean`、`dynsam/avg@n` 这类效果量。pro 第 23 步位移 2.56 而附近的版本切换只差 1.09 小时，正好对应公告里"移除 cyber 数据集"这一类改动。
3. **指标集本身在换**：`tags.json` 的 `versions[].n` 从 2019 变到 2029（pro，切换点 2026-09-19 03:07:03Z），`penalty/stage_credit_group/<metric>` 有 5 个指标中途才出现；序列层面 pro 有 218 个指标中途停止上报、232 个中途才开始上报，**其中绝大多数是 `partial/<cat>/<id>/<k>/{frac,n_tokens}` 这种新鲜度桶指标**——桶 1/2/3 只有在数据足够陈旧时才存在（pro 的桶 1 最早出现在第 2 步、桶 2 第 5 步、桶 3 第 6 步；flash 对应第 2/3/6 步）。这些"指标上线/下线"本身就是管线状态，不是模型状态。

**一个必须说清的局限**：`tags.json` 的 `last_seen` 几乎全部等于文件写入时刻（例如 pro 的 45 个 cyber 键 `last_seen` 都是 1789808290.716），所以**从 tags 看不出"谁被拿掉"**；移除只能从序列里的 null 缺口和公告推断（pro 的 cyber 序列只有 14 个非空步，与公告"把 cyber 从下一轮 pro 移除"一致）。另外 `notices.json` 的 5 条公告 `run` 字段全是 `null`，本文按正文主题把它对到对应 run。

## 八、偏相关：去掉共同时间趋势之后，哪些关系还活着

> **结论**：长度 ↔ 成绩的关系**完全是共同趋势**（控制步序号后归零）；数据陈旧度 ↔ 全局 KL 的关系**是真的**（控制后不降反升）；策略熵 ↔ 成绩控制趋势后**变号**。

**大白话**：两个数一起涨，可能因为它们真有关系，也可能因为"时间在往前走，两个都跟着变"。把两条序列各自对"第几步"回归、只留残差再算相关，就能把后一种情况剥掉。

**证据表（原始 Pearson / 控制步序号后的偏相关）**

| 指标对 | pro | flash | 判读 |

| `partial/avg_staleness` ~ `dynsam/avg@n` | 0.142 → 0.221 | 0.073 → 0.107 | 本来就弱 |

## 九、跨 run 可比性：两条 run 只有两个因子对得上

> **结论**：取交集指标后，pro 与 flash 的 PC1/PC2 能配对（|cos| 0.80/0.79，同一 24 步口径 0.76/0.70），PC3 及以后对不上（0.25～0.45）。逐指标的轨迹相关中位数只有 **0.156**，换成墙钟对齐更低（0.128）。

**大白话**：两条 run 跑的是同一套看板口径，但模型不同、步长不同、时长不同。如果"指标结构"是普适的，两条 run 的载荷应该高度一致；实际只有前两个宏观因子一致，单个指标基本各走各的。

## 十、不确定的、不稳定的、与预期相反的

1. **【不稳定】聚类不是稳定结构。** 留一步重跑去趋势聚类（去掉任意一步、重新标准化、重算相关、重聚类），与全样本的 **ARI 中位数只有 0.526（pro）/ 0.554（flash）**，最小值 0.371 / 0.448。加上"最高层合并距离都在 0.7 以上、没有空隙"，我的判读是：**第六节那份 15 簇地图是阅读工具，不是数据里客观存在的分块**；"哪个指标属于哪一簇"不要当结论引用。相比之下"最少 15 个指标能解释 83%"这种结论不依赖簇边界，更硬。
2. **【不稳定】flash 的 PC3 载荷几乎不可复现。** 留一步重算，PC1/PC2 的载荷余弦中位 0.998/0.997（最低 0.890/0.886），可以放心用；**flash 的 PC3 最小余弦只有 0.075**，去掉某一步后第三成分整个换方向。pro 的 PC3 最低 0.784。所以第五节里 PC3 的命名对 flash 只是一个粗糙描述。
3. **【与预期相反】"重启让指标跳得更大"在 pro 上不成立。** flash 上重启附近的去趋势位置统计量中位 5.92、其它 2.36（差 2.5 倍），pro 上反而是 2.42 对 3.44（重启附近的位移更小）。我原本以为重启是主要的"阶段制造者"，pro 的数据不支持这个一般化结论。
4. **【被推翻】"2000 个指标大部分只是在跟着时间涨"是错的。** 我一开始假设共同趋势会吃掉一切（所以先做了去趋势版本再聚类）。实际与步序号 |corr|≥0.95 的指标只有 **13/1389（0.9%，flash 27 个 = 1.8%）**，|ρ| 中位数只有 0.19。趋势确实集中在 PC1（得分与步序号相关 0.822/0.888，也就是时间解释了 PC1 方差的 **68% / 79%**），但逐指标去线性趋势并重新标准化之后，PC1 只从 21.0% 降到 **18.9%**（flash 18.6% → **17.6%**），而 PC2 从 14.6% 掉到 **10.3%**、flash 从 14.8% 掉到 **9.3%**——**第二因子里一半以上是非趋势波动**。趋势是背景，不是全部。
5. **【不确定】"有效自由度"本身的定义不唯一。** 参与率给 11.2/13.0；80% 方差给 14/17；90% 给 18/22；"贪心选 15 个指标"给的是另一套口径（83% 方差）。这几个数字互不矛盾（分别回答"等效独立信号数""要覆盖多少方差""最少读几个指标"），但引用时必须带口径。**不要只写"大概 12 个因子"就完事。**
6. **【不确定】跨 run 的逐指标低相关（中位 0.156）有一部分可能是"两条 run 本来就不该对齐"。** pro 是 24 步约 87 小时、flash 是 30 步约 80 小时，flash 第 1 步比 pro 第 1 步还早 0.85 小时；我用了两种对齐（步序号、墙钟插值）都得到低相关（0.156 / 0.128），所以我倾向于认为低相关是真的，但**不能排除"两条 run 的训练阶段根本不同"这个解释**。
7. **【不确定】偏相关的小样本噪声。** n=24/30 的偏相关标准误大约 0.2。表里"0.923 → 0.941"这种大幅超过噪声的可以信；"0.142 → 0.221"这种不能信。另外 `dynsam/num_target` 恒等于 1568、零方差，相关未定义（NaN），不是脚本出错。

## 附录 B：术语速查表

| 术语 | 一句话解释 | 可迁移的判断规则 |
|---|---|---|
| **z-score / 标准化** | 把每个指标减掉自己的均值、再除以自己的标准差，变成"均值 0、方差 1"的曲线 | 只要指标的**单位或量级不同**，做任何多元分析前都必须先标准化，否则方差大的指标会独吞主成分 |
| **相关矩阵 / 特征值** | 指标两两相关系数排成的方阵；它的特征值描述"方差沿某些方向有多集中" | 特征值总和恒等于指标个数；某个特征值除以指标数，就是该主成分解释的方差占比 |
| **主成分（PC）** | 把很多条曲线线性组合成互相不相关的新曲线，第一条解释方差最多 | 载荷（权重）很"平"时（最大载荷只有均匀值的 2～3 倍），不要给成分起一个过于具体的名字 |
| **参与率（PR）** | (Σλ)²/Σλ²，把整条特征值谱压缩成一个数，含义是"等效独立信号数" | λ 越集中，PR 越小。PR 远小于指标个数，说明指标之间高度重复；它是"有效自由度"最稳的一个口径 |
| **解释 80% 方差需要几个成分（n80）** | 累计方差占比第一次达到 80% 时的成分个数 | **不能跨样本量比较**：时间点越多，可分辨的成分越多，n80 会系统性变大。要比就必须对齐点数 |
| **Marchenko–Pastur 上边缘** | 如果所有指标彼此独立，样本相关矩阵的最大特征值大约能到 (1+√(d/n))²，即"纯噪声上限" | 特征值低于这个数就没有结构；本例中最小特征值都远高于它，说明该筛选器在这里不具区分力，要改用参与率 |
| **层次聚类 + 平均连接（UPGMA）** | 每次把最像的两个簇并起来；两簇距离取成员两两距离的平均 | 看**最高层合并距离**有没有空隙：没有空隙（本例都 >0.7）就说明"簇"是切出来的，不是长出来的 |
| **ARI（调整兰德指数）** | 两次聚类结果的一致程度，1 是完全一致、0 是随机 | 用它做稳定性检验：留一步重跑后 ARI 中位只有 0.5，就不要把簇成员当结论 |
| **变点检测 / 二分分割** | 在序列上找"性质变了"的位置；二分分割是贪心地每次找让段内方差掉最多的那个位置 | 必须同时看**惩罚强度**（本报告给无惩罚的位置统计量排序，避免结论依赖阈值）和**回退比**（跳完是否回来） |
| **回退比（reversion ratio）** | 变点后 3 步的新水平，与变点后更长时间的平均水平差多少，除以变点本身的位移 | ≈0 表示台阶保持（模型/配置真的变了），≈1 表示 3 步内退回（运维重置的瞬时冲击） |
| **偏相关（残差法）** | 两条序列各自对"第几步"回归、取残差后再算相关 | 水平相关高 ≠ 真有关系。共同趋势是这块看板上最常见的伪相关来源；控制时间后不掉甚至变大的（陈旧度↔KL），才是真关系 |
