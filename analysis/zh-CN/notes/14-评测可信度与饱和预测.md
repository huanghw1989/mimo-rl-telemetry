# 评测榜可信度与饱和预测：一个「掉分」到底算不算真变化

> 材料身份：**我方实测**。所有数字由脚本 `src/bench_report.ts` 从本地遥测
> `data/store/` 的原始 JSON 复算，脚本里没有任何硬编码结论数字；
> 复现命令见第十三节。文中凡标注【推断】的段落是模型外推或我的解释，不是数据直接证明的东西。
> 数据截至：**pro 第 24 步 / flash 第 30 步（flash 已 `ended`）**。
> 样本量是本文最大的约束：每个 (榜, run) 只有 16~25 个点，全文每个结论都报 n。
> 本文是 `notes/09-生成长度相关性分析.md` 的续作，不重复它已有的一阶差分/相关系数结论。

## 一、摘要：六条结论

1. **每个榜都有一条"别当真"的线。** 相邻两步的分数差要超过下面这个数才值得当真（95%，已扣掉趋势）：
   DeepSWE v1.1 pro **4.56 分** / flash **6.43 分**，In-house Coding Bench pro **1.55** / flash **1.68**，
   AutomationBench v1.0.6 pro **2.20** / flash **2.70**。在线主指标 `dynsam/avg@n` 的同一门槛是
   pro **4.1 个百分点** / flash **3.1 个百分点**。DeepSWE 的噪声是三个榜里最大的，比 In-house 大 3~4 倍。

2. **115 个单步变化里，只有 1 个经得起多重比较。** 不做校正时有 9 个"显著"（涨 8 / 跌 1）；
   按每个榜×run 内部做 Holm-Bonferroni 校正后只剩 **1 个**（In-house Coding / pro 第 16→18 步，+1.99 分，
   原始 p=0.0019）；如果把"这一步是否偏离趋势"当检验对象，**0 个**通过校正。
   也就是说：**这份看板上绝大多数"掉分/涨分"是测量噪声，不是模型变化。**

3. **三个榜的整体趋势是真的，最近的趋势看不出来。** 六个 (榜, run) 的 Theil–Sen 斜率全部为正，
   bootstrap 95% 区间全部不含 0；换成按墙钟时间（每小时的分数）算，排序和显著性完全一致。
   但只看**最后 5 个评测点**，六个斜率全部包含 0 —— 最近这几次评测**没有统计上可辨的进步**。
   对照：在线 `dynsam/avg@n` 在 pro 的**最后 5 步是显著下降的**（−1.09pp/步，CI [−1.93, −0.40]）。

4. **滞后 L 的点估计是 4~7 步（pro）/ 0~5 步（flash），不能钉死"4 步"。** 把共同趋势去掉之后，
   pro 的"生成长度 ↔ 基准分"互相关在 DeepSWE 上最优 L=4（bootstrap 84% 落在 L=4）、
   In-house 上 L=5（88% 落在 L=5）、Automation 上 L=7（67%）；flash 的分布是散的（众数 0~1，频次 30%~35%）。
   同一个 run、不同榜的最优 L 就不一样，所以数据支持的是"**存在一个 0~7 步量级的正滞后，量级约 4 步**"，
   不支持"滞后精确等于 4"。另外，标称步号和"这个分数什么时候能被读到"是两件事（见第六节）。

5. **饱和外推基本不可靠，只有分段模型敢下结论，而它说的是"已经到平台了"。**
   在外推意义上（**以下全是【推断】**）：平滑模型（指数饱和 / Gompertz / 逻辑斯蒂）在 6 个榜序列里有 5 个
   的"平台值"连置信区间都定不下来（区间上界跑到几万甚至 10¹⁰⁸ 量级，因为 c→0 时 a→∞ 不可识别）；
   唯一能识别的是 In-house Coding / flash，它的四个模型给出 61.6~67.2 的平台，跨度 5.5 分。
   分段线性到平台模型在 6 个榜序列里的估计平台**全部低于或接近最后一个观测值**。
   对 `dynsam/avg@n`：pro 的四个模型都给出 0.614~0.646 的平台（实测峰值 0.643@第 20 步），
   剩余空间 1.7~4.9pp，而单步噪声就是 4.1pp —— **pro 的剩余空间与噪声同量级，等于说"看不出来还有多少"**；
   flash 的平台在 0.648（分段）到 0.766（指数）之间，模型跨度 9.3pp，**这个预测不可信**。

6. **"flash 只是跑得快"这个说法，只有在按钱对齐时才反过来。** 同一步号上 pro 领先（`avg@n` 24 个共同步里
   pro 高 22 次；DeepSWE 16/16、In-house 15/15 全部 pro 高）；同累计 token 上 pro 也领先
   （20B token 时 DeepSWE pro 63.53 / flash 58.90）；**同累计成本上 flash 领先全部对比点**
   （$0.6M 时 `avg@n` 0.600 / 0.618，DeepSWE 63.23 / 65.68，In-house 60.92 / 62.24，Automation 46.93 / 52.22）。
   原因是 flash 的 `cost/rate_per_s`（成本速率，每秒烧的钱）正好是 pro 的一半，而它每步烧的 token 更多
   （30 步 81.4B vs pro 24 步 56.0B）。所以 flash 的优势是**单位成本效率**，不是样本效率。

现在榜到第 **18/25** 步，而训练到第 **24/30** 步，缺口变成了 pro **6 步**（AutomationBench 缺 8 步）、flash **5 步**。

**三个关键口径决定**：

1. **"单步测量噪声"用趋势残差，不用相邻差分。** 相邻差分里混着趋势本身（每步 +0.28~+0.57 分），
   而且当序列存在负的一阶自相关时，相邻差分还会**高估**噪声（DeepSWE/flash 的残差一阶自相关是 −0.461，
   它的相邻差分标准差 3.98 分，去掉自相关后单点噪声只剩 2.25 分）。所以主口径是
   **Theil–Sen 去趋势后残差的标准差 σ_pt**，相邻差分口径作为对照同时报出。
2. **MDE（minimum detectable change，最小可检测变化）**：单点噪声 σ_pt 下，两个独立测量之差的标准误是
   σ_pt·√2，所以"这个差值要多大才值得当真"是 `MDE = 1.96 · σ_pt · √2 = 2.7716 · σ_pt`。
   报告里所有 MDE 都是 95% 口径。
3. **时间轴**：主口径按**训练步号**；稳健性检验按**墙钟时间**（`axis.walls` 是每一步完成的墙钟时刻，
   已逐点核对与 `status.events` 里同名步的时间戳完全一致）。因为两条 run 的 `cost/rate_per_s` 全程恒定，
   "按墙钟"与"按成本"是同一件事，不再单列。

## 三、每个榜的测量误差有多大

**结论**：DeepSWE 的单步噪声比另外两个榜大 3~4 倍；三个榜的 MDE 分别是 4.6~6.4 分、1.6~1.7 分、2.2~2.7 分。
115 个单步变化里只有 1 个经得起多重比较。

**人话**：这三个榜不是同一把尺子。DeepSWE 那道 −6.05 分的大跌看上去很吓人，但它连"单独看"的显著性都只是
勉强够（p=0.046），放到该序列 22 次比较里就完全不成立了。反过来，In-house 榜因为噪声小得多，
它的"+1.99 分"才是这份数据里唯一站得住的单步变化。

### 3.1 每个 (榜, run) 的噪声与 MDE

| 榜 | run | n | 相邻步 σ_Δ | σ_pt（残差 SD） | **MDE(95%)** | σ 区间推出的 MDE 区间 | MDE（相邻差分口径） | 趋势 τ/步 |
|---|---|---|---|---|---|---|---|---|
| DeepSWE v1.1 | pro | 17 | 2.01 | 1.59 | **4.56** | [3.25, 6.82] | 3.93 | +0.567 |
| DeepSWE v1.1 | flash | 23 | 3.98 | 2.25 | **6.43** | [4.79, 8.91] | 7.80 | +0.506 |
| In-house Coding | pro | 17 | 0.64 | 0.56 | **1.55** | [1.15, 2.41] | 1.25 | +0.388 |
| In-house Coding | flash | 23 | 0.66 | 0.49 | **1.68** | [1.05, 1.94] | 1.29 | +0.328 |
| AutomationBench | pro | 16 | 0.95 | 0.79 | **2.20** | [1.61, 3.47] | 1.85 | +0.276 |
| AutomationBench | flash | 25 | 1.39 | 0.97 | **2.70** | [2.10, 3.78] | 2.73 | +0.355 |
| `dynsam/avg@n`（对照，单位=百分点） | pro | 24 | 1.30 | 1.49 | **4.12** | [3.19, 5.84] | 2.55 | +0.37 |
| `dynsam/avg@n`（对照） | flash | 30 | 1.81 | 1.11 | **3.08** | [2.45, 4.17] | 3.55 | +0.48 |

读法：DeepSWE/flash 的"相邻差分口径"（7.80）比主口径（6.43）还大，是因为它的残差一阶自相关是 **−0.461**，
差分噪声被 `(1−ρ)` 放大，而主口径已经把这部分剥掉了。**这就是为什么不能只用相邻差分标准差估噪声**——
当序列在"高分步/低分步"之间来回摆时（DeepSWE/flash 就是），它会系统性高估。

### 3.2 反推"等效题目数"

假设 1：每步的榜分是"Q 道题、每题 3 次独立采样"的平均通过率，各题难度同质；
假设 2：单点噪声全部来自采样。这时 σ_pt² = p(100−p)/N（p 用百分点），N 就是等效的独立伯努利试验数。

| 榜 | Q_pro ≈ | Q_flash ≈ | 两个 run 估计的比值 | 说明 |
|---|---|---|---|---|
| DeepSWE v1.1 | 290 | 150 | 1.94 | 三个榜里题目最少（或单题方差最大） |
| In-house Coding Bench | 2536 | 2203 | 1.15 | 两个 run 高度一致 |
| AutomationBench v1.0.6 | 1325 | 879 | 1.51 | 中间 |

这是【推断】，不是看板给的事实——看板没给题目数（`content/metrics.json` 的 `benchmark/deepswe` 条目明确写了
"没给题目数量、采样参数或判分细节"）。两点评判：

- **有可能对**：DeepSWE 这类 SWE-bench 衍生榜通常只有几百道题，反推的 150~290 道是合理量级；
  In-house 和 AutomationBench 反推出上千道，说明它们的题目数远多于 DeepSWE，这正好解释了为什么它们的曲线平滑得多。
- **不可全信**：同一份题集上 pro 与 flash 的反推值在 DeepSWE 上差了 1.94 倍。如果题目数是同一个数，
  这个比值应该接近 1，所以这个反推至少有一半的误差来自"噪声不全是采样噪声"（模型本身在漂，
  以及每周评测用的题目子集可能不同）。**把 Q 当作"等效独立题目数的下界"用，不要当作真实题目数。**

### 3.3 完整判定：哪些单步变化该当真

115 个单步变化（含缺步造成的跨 2 步变化）：

| 口径 | 显著个数 | 涨 / 跌 |
|---|---|---|
| 朴素 5%（只跟序列内噪声比，不校正） | 9 | 8 / 1 |
| Holm-Bonferroni 校正后（组内 15~24 次比较） | **1** | 1 / 0 |
| 相对趋势的偏离 + Holm 校正 | **0** | – |

各组的明细：

| 组 | 变化数 | 朴素显著 | Holm 后 | 最小 p |
|---|---|---|---|---|
| DeepSWE / pro | 16 | 1 | 0 | 0.0167 |
| DeepSWE / flash | 22 | 0 | 0 | 0.0950 |
| In-house / pro | 16 | 3 | **1** | 0.0019 |
| In-house / flash | 22 | 2 | 0 | 0.0073 |
| AutomationBench / pro | 15 | 1 | 0 | 0.0264 |
| AutomationBench / flash | 24 | 2 | 0 | 0.0119 |

唯一活下来的一个是 **In-house Coding / pro 第 16→18 步 +1.99 分**（跨 2 步，原始 p=0.0019，
Holm 阈值 0.05/16=0.0031）。但要注意它的身份：这一步的**趋势本身**就贡献了 +0.78 分，
扣掉之后残差 +1.21 分只有 1.53σ（p=0.126）。所以更准确的说法是"它是这份数据里最像真变化的一步，
但它的显著性有一半来自 2 步的时间跨度"。

其余 8 个朴素显著的变化（全部在 Holm 下失效）：

| 组 | 步 | Δ | 原始 p | 备注 |
|---|---|---|---|---|
| DeepSWE / pro | 7→8 | +4.80 | 0.0167 | 单步，MDE 内 |
| In-house / pro | 3→4 | +1.64 | 0.0104 | 单步，刚过 MDE 1.25（相邻差分口径） |
| In-house / pro | 8→9 | +1.48 | 0.0208 | 同上 |
| In-house / flash | 11→12 | +1.77 | 0.0073 | 单步，MDE 内（此序列有两个缺口） |
| In-house / flash | 15→16 | +1.38 | 0.0364 | 单步，MDE 内 |
| AutomationBench / pro | 6→7 | −2.10 | 0.0264 | 单步，是这份数据里少数几个"低于趋势"的点 |
| AutomationBench / flash | 6→7 | +3.00 | 0.0311 | 跨 2 步 |
| AutomationBench / flash | 14→15 | +3.50 | 0.0119 | 单步，超过 MDE 2.70；**这就是 flash 全程最高点 51.2 那一步** |

**关于 `notes/09` 那条结论的更新**：它说 flash 第 11 步的 −6.05 分"z≈−1.77，排除不了评测噪声"。
用趋势残差口径重算，这一步的偏离是 −6.56 分，**z=−2.00，未校正 p=0.0456** —— 名义上刚好跨过 0.05，
但仍然排除不了噪声，理由有两个：一是该序列有 22 次比较，Holm 阈值是 0.0023；二是"−6.05 是全程最大单步跌幅"
本身就是事后挑出来的最大值，多重比较效应会比逐次检验更严重。**结论不变，但理由要比 notes/09 更硬：
不是"z 不够大"，而是"它是在 115 个变化里挑出来的最大值"。**

## 四、趋势是不是真的

**结论**：整体趋势在两种时间轴下都显著，排序也一致；最近 5 个评测点看不出趋势。

**人话**：把整个训练过程拉长看，三个榜都在稳定上涨，这个结论很稳。但你要是只盯着最近这几次评测，
那是"噪声里没有趋势"——不是"停住了"，是**样本太少看不出来**。

### 4.1 全序列趋势（Theil–Sen 稳健斜率 + bootstrap 4000 次）

| 榜 | run | n | 每步（分） | 95% CI | 每小时（分） | 95% CI | 末点相对首点 |
|---|---|---|---|---|---|---|---|
| DeepSWE | pro | 17 | +0.567 | [0.430, 0.743] | +0.171 | [0.129, 0.256] | +9.05 |
| DeepSWE | flash | 23 | +0.506 | [0.354, 0.613] | +0.194 | [0.140, 0.249] | +16.23 |
| In-house | pro | 17 | +0.388 | [0.312, 0.473] | +0.121 | [0.092, 0.173] | +6.13 |
| In-house | flash | 23 | +0.328 | [0.284, 0.368] | +0.128 | [0.103, 0.159] | +8.10 |
| AutomationBench | pro | 16 | +0.276 | [0.233, 0.480] | +0.101 | [0.076, 0.144] | +3.60 |
| AutomationBench | flash | 25 | +0.355 | [0.300, 0.400] | +0.143 | [0.119, 0.170] | +8.30 |

两种口径给出的排序完全一致：**DeepSWE 涨得最快 > In-house > AutomationBench**（按步号）。
按墙钟算，两条 run 每小时涨的分数接近（0.17 vs 0.19、0.12 vs 0.13、0.10 vs 0.14），
说明"哪个榜涨得快"不是评测节奏造成的伪影。六个斜率全部不含 0，趋势是真的。

### 4.2 最近的几次评测有没有可辨的进步

| 榜 | run | 最后 5 点区间 | 净变化 | 斜率（分/步） | 95% CI | 排除 0？ |
|---|---|---|---|---|---|---|
| DeepSWE | pro | 14→18 | +2.86 | +1.115 | [−0.232, 1.553] | 否 |
| DeepSWE | flash | 21→25 | +5.31 | +1.106 | [−0.883, 3.242] | 否 |
| In-house | pro | 13→18 | +1.13 | −0.070 | [−0.433, 0.639] | 否 |
| In-house | flash | 21→25 | +0.60 | +0.252 | [−0.105, 0.630] | 否 |
| AutomationBench | pro | 12→16 | +1.10 | +0.475 | [−0.313, 0.800] | 否 |
| AutomationBench | flash | 21→25 | +1.70 | +0.538 | [−0.217, 0.925] | 否 |

**六个全部排除不了 0。** 把窗口放到最后 8 个点，只有两个变得可辨：
In-house/flash +0.142 分/步 [0.050, 0.303]、AutomationBench/pro +0.563 [0.233, 0.667]。
所以对"最近这几次评测"这个问题，诚实的答案是**没有统计上可辨的进步，也没有统计上可辨的停滞**。

**对照在线主指标**（它每一步都有，n 大得多）：

| run | 全程斜率 | 最后 5 步净变化 | 趋势预期 | 差 | z | 最后 5 步斜率 | 95% CI | 排除 0？ |
|---|---|---|---|---|---|---|---|---|
| pro | +0.37pp/步 | **−4.67pp** | +1.46pp | −6.13pp | −1.95 | **−1.09pp/步** | [−1.93, −0.40] | **是（下降）** |
| flash | +0.48pp/步 | +0.55pp | +1.93pp | −1.37pp | −0.48 | +0.20pp/步 | [−0.93, 1.36] | 否 |

pro 在主指标上的末段回落是这份数据里**唯一一个"最近在变差"的显著信号**，但它在离线榜上没有对应读数
（pro 的榜最晚到第 18 步，回落发生在第 20 步之后）——所以是"只有在线指标看见、无法外部验证"的回落。

## 五、自相关与有效样本量

**结论**：pro 的评测序列一阶自相关 0.25~0.32，有效样本量只剩一半；但三个榜的趋势在考虑自相关之后
**仍然显著**（Newey-West p≤0.0026、分块置换 p≤0.0008）；单步变化层面，考虑了自相关与多重比较后
**一个都不剩**。

**人话**：相邻的评测点不是独立的信息——第 12 步好，第 13 步往往也好。这会让"20 个点"实际上是"10 个点"，
把显著性算高了。把它扣掉之后，**"在涨"这件事依然成立，但"这一步涨了"这件事基本都不成立**。

### 5.1 一阶自相关与有效样本量

有效样本量用 AR(1) 标准式 `n_eff = n(1−ρ)/(1+ρ)`；ρ 是 Theil–Sen 残差的一阶自相关。

| 榜 | run | n | ρ₁(残差) | ρ₁(一阶差分) | n_eff | n_eff/n |
|---|---|---|---|---|---|---|
| DeepSWE | pro | 17 | +0.282 | −0.213 | 9.5 | 0.56 |
| DeepSWE | flash | 23 | −0.461 | −0.699 | 23.0（公式给 62.4，超过 n，已截到 n） | 1.00 |
| In-house | pro | 17 | +0.251 | −0.396 | 10.2 | 0.60 |
| In-house | flash | 23 | +0.087 | +0.057 | 19.3 | 0.84 |
| AutomationBench | pro | 16 | +0.316 | −0.271 | 8.3 | 0.52 |
| AutomationBench | flash | 25 | −0.002 | −0.015 | 25.0 | 1.00 |

DeepSWE/flash 的 ρ₁ 是 −0.461，说明它**不是**平滑的自相关序列，而是"高低交替"（一步高一步低）。
这种情况下朴素的 OLS 检验是偏保守的，所以本文对 n_eff 做了上限截断（不超过 n），
并保留公式原始值在 JSON 里（`n_eff_formula_raw`）备查。

### 5.2 趋势显著性的六种算法对照

| 榜 | run | n | p（OLS 朴素） | p（n_eff 校正） | p（Newey-West） | p（置换：直接打乱 y） | p（置换：环形分块残差） | p（差分符号翻转） |
|---|---|---|---|---|---|---|---|---|
| DeepSWE | pro | 17 | 0.0000 | 0.0005 | 0.0000 | 0.0002 | 0.0002 | 0.260 |
| DeepSWE | flash | 23 | 0.0000 | 0.0000 | 0.0000 | 0.0002 | 0.0002 | 0.119 |
| In-house | pro | 17 | 0.0000 | 0.0000 | 0.0000 | 0.0002 | 0.0002 | 0.132 |
| In-house | flash | 23 | 0.0000 | 0.0000 | 0.0000 | 0.0002 | 0.0002 | 0.753 |
| AutomationBench | pro | 16 | 0.0000 | 0.0026 | 0.0000 | 0.0008 | 0.0002 | 0.564 |
| AutomationBench | flash | 25 | 0.0000 | 0.0000 | 0.0000 | 0.0002 | 0.0002 | 0.994 |

（0.0002 = 5000 次置换里的下限。分块置换用长度 ⌈n^(1/3)⌉ 的环形块重排残差，保留自相关结构。）

**六种方法里，扣掉自相关的三种（n_eff、Newey-West、分块置换）全部给出 p≤0.0026。**
符号检验（涨的步数 vs 跌的步数）最弱，一个都不显著（最接近的是 In-house/flash 的 16 涨 / 6 跌，p=0.055）——
因为符号检验丢掉了幅度信息，在 n≈20 上本来就没什么功效。

### 5.3 把自相关算进去之后，还有几个"进步/退步"显著

- 单步变化（115 个）：朴素 9 个显著 → **Holm 校正后 1 个** → 相对趋势 + Holm 后 **0 个**。
- 序列趋势（6 条）：全部显著，且扣除自相关后依然显著。
- 末段趋势（6 条最后 5 点）：0 个显著。

一句话：**「这个榜整体在涨」经得起自相关；「这一步涨了/掉了」经不起。**

## 六、滞后结构：评测落后训练多少步

**结论**：把共同趋势去掉后，pro 的"长度 ↔ 榜单分"互相关确实有一个 4~7 步的最优滞后
（bootstrap 分布很集中），但**三个榜给不出同一个 L，flash 更给不出**。所以数据支持"有滞后、量级约 4 步"，
不支持"滞后就是 4 步"。

**人话**：评测榜上的"第 12 步分数"是**第 12 步那个模型**考出来的，但**要等到训练跑到第 13 步才看得到**。
官方公告自己说了成绩是补发的。所以"榜到第 18 步"不等于"你有第 18 步的信息"。

### 6.1 互相关扫描（L=0~8）

必须先去掉趋势。直接用水平值扫，任何 L 的相关系数都有 0.82~0.98（DeepSWE/flash 的 `train/passrate` 在 L=0 是 0.819），
因为两条线都在随时间涨 —— 那是伪相关，不是滞后结构。下面是**去趋势后**的结果：

| 榜 | run | 训练侧指标 | 最优 L | r（去趋势） | 该 L 的配对数 | bootstrap 众数 L（频次） | 最优附近同样本噪声的 L |
|---|---|---|---|---|---|---|---|
| DeepSWE | pro | `ctx_response_length/mean` | **4** | +0.663 | 13 | 4（84%） | 3,4,5 |
| DeepSWE | pro | `train/passrate/avg_passrate` | **4** | +0.389 | 13 | 4（43%） | 0~8 |
| DeepSWE | pro | `critic/score/mean` | 1 | +0.533 | 16 | 1（67%） | 0~8 |
| DeepSWE | pro | `dynsam/avg@n` | （6） | −0.367 | 11 | 1（26%） | 0~8 |
| In-house | pro | `ctx_response_length/mean` | **5** | +0.842 | 12 | 5（88%） | 4,5,6 |
| In-house | pro | `train/passrate/avg_passrate` | **5** | +0.756 | 12 | 5（69%） | 2,4~8 |
| In-house | pro | `critic/score/mean` | 1 | +0.649 | 16 | 2（41%） | 0~8 |
| AutomationBench | pro | `ctx_response_length/mean` | **7** | −0.472 | 9 | 7（67%） | 5~8 |
| AutomationBench | pro | `train/passrate/avg_passrate` | 0 | −0.620 | 16 | 6（81%） | 6,7,8 |
| DeepSWE | flash | `ctx_response_length/mean` | 1 | +0.339 | 22 | 1（32%） | 0~8 |
| In-house | flash | `ctx_response_length/mean` | 0 | +0.253 | 23 | 0（35%） | 0~8 |
| AutomationBench | flash | `ctx_response_length/mean` | 5 | +0.437 | 20 | 5（38%） | 0~8 |

读法：

- **pro 上"长度/训练通过率 → 榜单分"确有滞后结构。** `ctx_response_length/mean`（本步训练轨迹的平均生成长度）
  在三个榜上分别给 L=4/5/7，bootstrap 下 84%/88%/67% 的重采样把最优 L 放在同一个值上 —— 这个集中度说明
  滞后不是纯噪声。`train/passrate/avg_passrate`（进入训练那批题的平均通过率）给出的 L=4/5 与它一致。
- **但三个榜的 L 不一致（4 / 5 / 7），flash 的分布在 0~8 上摊平。** 所以"最优 L 是 4"这个说法，
  只在 DeepSWE/pro 上成立；把它推广成"评测整体落后 4 步"是过度概括。
- **`dynsam/avg@n`（在线主指标）完全给不出滞后。** 它在 pro 上的去趋势相关在 L=0~5 全是负的
  （L=0 是 −0.36、L=6 才有 −0.37）—— 因为在线指标和离线榜都在同一批数据上被推着走，
  去趋势后剩下的就是噪声。**用在线指标去猜评测滞后没有意义。**
- **把 L 往大了扫会掉样本。** L=8 时 DeepSWE/pro 只剩 9 对点，相关系数的 95% 临界 |r| 是 0.666，
  L=8 的 |r| 基本都低于这个线。所以 L=7、L=8 上的"最优"本来就不可信。

### 6.2 公告补发：标称步号 ≠ 值的可达时间

`notices.json` 里有一条（时间戳 t=1789581497.496，即 **2026-09-16T17:58:17Z**）：

> "we have updated the latest deepswe results for flash step 12 & pro step 8. we will keep posting as the offline evaluation results come out."

对着 `axis.walls` 反查这条公告发出的时刻：

| run | 补发的标称步 | 该步完成时刻 | 公告时刻该 run 已完成 | 标称步到公告之间的训练步 | 墙钟间隔 |
|---|---|---|---|---|---|
| pro | 第 8 步 | 1789562521.98（2026-09-16T12:42:02Z） | 第 10 步 | 2 步 | **5.27 小时** |
| flash | 第 12 步 | 1789567997.15（2026-09-16T14:13:17Z） | 第 13 步 | 1 步 | **3.75 小时** |

**这说明"标称第 12 步"的值在那一步跑完之后还要过 1~2 个训练步（数小时）才能被读到。**
于是有两个不同的"进度"概念：

- **模型身份进度**：分数描述的是第几步的 checkpoint（这就是本文用的口径，x 轴 = 标称步号）。
- **信息可达进度**：截至某个时刻，你手里最新的一条评测是哪一步的。

任何"**在某时刻我们已知什么**"的分析（比如复盘决策、算 as-of 指标）必须用后者；
本文做趋势和饱和拟合时用前者，因为要问的是"模型在第 s 步长什么样"。
如果要做 as-of 口径，最保守的做法是把观察窗口整体右移 1~2 步（约 4~5 小时）。
另一个后果是：**现在的缺口（pro 6~8 步、flash 5 步）是"名义缺口"，加上补发延迟，实际的信息缺口更大。**

## 七、饱和预测：还剩多少空间（★本节全部是推断/外推）

**结论**：三种以上的饱和模型在这份数据上给出的答案分歧很大，**大部分序列的"平台值"根本定不下来**。
唯一比较一致的是：**pro 的在线主指标剩余空间（1.7~4.9pp）与单步噪声（4.1pp）同量级**，
也就是"看不出来还有多少"。flash 在停止时的状态，用分段模型读是"已到平台"，用平滑模型读是"还差 8~10pp"，
**两种读法都能自圆其说，数据不足以判定**。

**人话**：20 来个点、还在往上走的曲线，你想问"它最后能到哪"，数学上是可以硬算的，
但算出来的答案对模型选择极其敏感。这篇报告不挑好看的模型报数，而是把三个以上模型的答案并排放在一起，
让你看到分歧有多大。

### 7.1 拟合方法与"可识别"判据

四种模型，参数都用"profile + 一维黄金分割"求解（给定非线性参数 c 或 K 之后，剩余参数是线性的，可精确解出）：

| 模型 | 形式 | 参数 |
|---|---|---|
| `exp_saturation` | y = a − b·exp(−c·x) | a=平台，b=总涨幅，c=速率 |
| `gompertz` | y = a·exp(−b·exp(−c·x)) | a=平台 |
| `logistic` | y = K/(1+exp(−r(x−x₀))) | K=平台 |
| `piecewise_linear_plateau` | y = min(α+βx, P) | P=平台，断点网格搜索 |

参数区间用**残差 bootstrap**（重抽残差加回拟合曲线，重拟合 500 次）。加了一个**可识别性判据**：
若平台值的 95% bootstrap 区间宽度超过"数据极差（max−min）的 2 倍"，就标记 `identifiable=false`。
理由很直接：指数/Gompertz 在 c→0 时 a→∞，用有限窗口的数据**在数学上无法区分"已经接近平台"和"还在缓慢线性上升"**。
本报告不把这种数值当预测用。

### 7.5 交叉检验：flash 在第 30 步停下，和饱和一致吗

**结论**：**数据判不了，而且更倾向于"不一致"。** 具体地：

- flash 最后两步是 **0.6623（第 29 步，全程最高）→ 0.6435（第 30 步）**，跌了 **1.88pp**，
  小于单步 MDE **3.08pp** → 这次回落本身**在噪声里**，不能说明模型变差。
- 分段模型：平台 0.6483，95% CI **[0.6331, 0.6598]，把最后一步 0.6435 包在里面** → 与"已饱和"一致，
  剩余空间 +0.47pp（0.15 倍 MDE）。
- Gompertz：平台 0.7415，CI [0.6847, 0.9745]，**整个 CI 都在最后一步之上** → 与"已饱和"不一致，
  剩余 9.8pp（3.2 倍 MDE）；它说"要再走 37.6 步（CI [13.8, 116.6]）才走完已见趋势的 90%"。
- 逻辑斯蒂：平台 0.7271，CI [0.6792, 0.8948]，同样在最后一步之上 → 剩余 8.4pp（2.7 倍 MDE），还需 28.9 步。

所以：**3 个可识别模型里 1 个支持"停得合理"，2 个不支持。** 而且这两个模型还说了
"就算按你现在的曲线，也还差 28~38 步才走完 90%"。

**但我要把反向的证据也列出来**（这一段才是我对这个问题的独立数据检验）：

1. **末段确实在走平。** 第 23~30 步的净变化只有 **+0.87pp**，而按全程斜率（+0.48pp/步）这 8 步
   "应该"涨 3.37pp；差 −2.5pp，z≈−0.66（噪声内），但方向与"走平"一致。最后 5 步净变化 +0.55pp，
   同样远小于按全程斜率的预期 +1.93pp（z=−0.48）。**用 n=8~30 的数据，看不出"+0.87pp 是平台的到来"，
   也看不出"它是继续上涨路上的一段低谷"。**
2. **相邻的榜在同时段也在走平。** flash 第 18~25 步（它最后一次送评的窗口）DeepSWE 净 +0.89、
   In-house +1.01、AutomationBench +1.20，全部落在各自 MDE 附近或以内。
3. **"多训 5 步能不能买到超过 3pp 的 avg@n"这个问题，用这份数据无法回答**，因为
   flash 的末段趋势斜率 +0.20pp/步的 95% CI 是 [−0.93, +1.36] —— 它同时兼容"还在涨 1.36pp/步"
   和"在跌 0.93pp/步"。

**判断**：`notes/07` 的"停止与饱和一致"这个结论，**在当前数据上只能得到"不能排除"，得不到"支持"**。
如果一定要给倾向：**分段模型（唯一一个不需要假设曲线形状的模型）支持它，两个需要假设曲线形状的模型不支持它**，
而分段模型在 AICc 上并不比它们差（差距 < 2）。所以我的表述是：
**"没有证据说停止是错的，也没有证据说已经到顶；用最不依赖假设的模型读，停在第 30 步与平台一致。"（推断）**

## 八、pro 与 flash 横向比较

**结论**：**按步号 pro 领先，按累计成本 flash 领先，按累计 token pro 领先。** flash 的优势完全来自

1. **flash 每步烧的 token 更多**：30 步共 81.4B，pro 24 步共 56.0B（`perf/total_num_tokens` 逐步求和，
   与 `totals.tokens_cum` 精确相等）。这与"flash 的回答更长"一致（`notes/09`：flash 生成长度 ×2.13、pro ×1.68）。
2. **flash 每步墙钟更短**：到第 24 步 pro 用了 93.3 小时，到第 30 步 flash 用了 81.8 小时。
   因为 `rate_per_s` 恒定（pro 5.71/s、flash 2.855/s，比值精确 2.000），按墙钟与按成本是同一件事。
3. **但 token 效率是反的**：同样的 token 数下 pro 的分数更高，说明 pro 的样本效率（每 token 学到的能力）更优；
   flash 的优势来自"每 10 亿 token 成本只有 pro 的三成"（`notes/07` 的两条反推路径）。

**所以"flash 领先 pro"只在"按钱算"这个口径下成立，而它衡量的不是模型能力，是单位算力的性价比。**

## 九、"边训边测是否导致过拟合"这个疑问，数据能给到什么

**结论**：数据给的是**反方向的信号** —— 外部榜（DeepSWE）的进步速度**快于**自家榜（In-house Coding），
两个 run 的斜率差都是 −0.176/−0.177 分/步，配对 bootstrap 的 95% CI 都排除 0。
如果"自家题被过拟合"成立，应该看到相反的方向。**但这不能证明评测集干净**，
它只能说明"这块看板上没有出现过拟合自家题的迹象"。

**人话**：把训练分布上的通过率（`dynsam/avg@n`）和固定测试集分数画在一起，中间那条缝就是"gap"。
如果 gap 随着训练越来越大，说明在线读数越来越不代表真实能力。这里 automation 的 gap 确实在变大，
但 in-house 榜的差距反而在缩小，DeepSWE 基本不动。

### 9.1 gap 随步的变化（gap = `avg@n`×100 − 榜分，单位都是百分点）

| 榜 | run | n | gap 首→末 | 斜率（点/步） | 95% CI | 排除 0？ |
|---|---|---|---|---|---|---|
| DeepSWE | pro | 17 | −1.94 → −5.72 | −0.163 | [−0.313, +0.021] | 否（趋向扩大） |
| DeepSWE | flash | 23 | +2.70 → −0.82 | +0.033 | [−0.097, +0.225] | 否（不动） |
| In-house | pro | 17 | −1.07 → −1.93 | +0.050 | [−0.043, +0.168] | 否 |
| In-house | flash | 23 | −2.46 → **+2.15** | **+0.197** | [+0.099, +0.298] | **是（收窄）** |
| AutomationBench | pro | 16 | +10.27 → +13.75 | **+0.178** | [+0.023, +0.303] | **是（扩大）** |
| AutomationBench | flash | 25 | +8.07 → +12.48 | **+0.160** | [+0.076, +0.274] | **是（扩大）** |

- **AutomationBench 的 gap 在两条 run 上都显著扩大（+0.16~+0.18 点/步）**。含义是：
  在线通过率每步涨 0.37~0.48pp，而 AutomationBench 只涨 0.28~0.36 分，
  差额（+0.10~+0.16pp/步）累计成了 6 步 4 个百分点的裂缝。
  两种解释都成立：(a) 在线指标随数据配比漂移，越来越偏离固定测试集；
  (b) AutomationBench 更快饱和（它的全程斜率确实是三个榜里最低的）。**数据分不开这两者。**
- **In-house/flash 的 gap 在显著收窄**，也就是说 flash 在自己的题集上进步**比**在线指标**更**快。
- **DeepSWE/pro 的 gap 趋向扩大但不显著**（−0.163，CI 上界 +0.021）。

### 9.2 自家题 vs 外部题

在两条 run 共同的步号上（pro 16 个共同步、flash 23 个）做配对比较：

| run | 共同步 | In-house 净变化 | In-house 斜率 | DeepSWE 净变化 | DeepSWE 斜率 | 斜率差（In-house − DeepSWE） | 95% CI | 排除 0？ |
|---|---|---|---|---|---|---|---|---|
| pro | 16 | +6.13 | +0.384 | +9.05 | +0.560 | **−0.176** | [−0.355, −0.041] | **是** |

**这个结论有一个必须说清的反驳**：flash 的 DeepSWE 起点（48.67）比 In-house（53.83）低了 5.16 分，
起点低本身就可能涨得快（天花板效应），而 pro 的两个起点几乎相同（58.41 与 57.54）却也有同样的斜率差 ——
所以天花板效应不能完全解释它，但**这份数据无法把"天花板效应"彻底排除**（没有可比尺度的第三方参照）。
把它当作"一条反对过拟合假说的证据"，不要当作"证明没有过拟合"。

### 9.3 为什么仅凭这块看板无法判定污染，以及还需要什么

**能说的**：

- 看板提供的是分数与步号，**没有提供任何一条关于测试题是否出现在训练数据里的信息**。
- `train/passrate/passrate_0_ratio`（全错题占比）在 pro 上从 0.92% 涨到 3.89%（第 23 步），
  flash 从 0.91% 单调涨到 8.30% —— 这是"训练数据里能被做对的题越来越多，全错的题在累积"，
  与污染检测无关（它讲的是训练分布内部的难度结构）。
- `penalty/stage_credit_group/*` 里有"疑似绕过评测的尝试比例"这类字段（`notes/09` 第 6 节已分析），
  但差分相关不显著（pro 0.263 / flash 0.318，均未过 0.05），**不足以支撑"有刷分行为"**。
- 上一条的"自家题涨得慢、外部题涨得快"是**反向证据**，但它不构成排除。

**要判定污染，还需要至少这些数据**（前三条来自外部文献的普遍做法）：

1. **测试集的逐题身份 + 训练语料的可检索索引。** 有了这两样才能做 n-gram/字符串重叠检测、
   近似重复检测（MinHash/SimHash）、以及 canary 串注入。看板给不了。
2. **逐题成绩而不是汇总分。** 现在只有总分（而且只有 3 次采样），拿不到"哪几道题被做对了"。
   污染的特征是"少数特定题从 0/3 变成 3/3"，在总分上被平均掉了。
3. **干扰项/对照实验**：同一 checkpoint 在一份**确认从未进入训练**的平行题集上评测，
   看两份题集的分数差是否随训练扩大；或对训练语料做去污染重训（ablation）。
4. **模型内部信号**：memorization / membership inference（成员推断）不能只看 log-prob，
   因为文献已表明 RL 阶段会把这类信号掩盖掉（见下）。
5. **判分链路日志**：`env/possible_leak`（pro 第 19 步出现过全轮唯一一次非零）、
   harness 的沙箱与网络访问记录。这些只能排除"运行时泄露"，不能排除"数据里的重叠"。

**外部文献支持"只看分数看不出污染"这个判断**：

- **Nourbakhsh 等（GEM 2026，Outstanding Paper）系统综述了 55 篇污染检测研究**，结论原文是
  "Across studies, no detection method is consistently reliable across contamination tiers, model-access settings,
  and training stages"，并且特别指出"**RL/post-training contamination auditing is only beginning to mature**"，
  报告的性能膨胀估计跨度 6%~40%。
  （[Are LLM Benchmarks Already Contaminated? A Systematic Review of Contamination Detection Methods](https://aclanthology.org/2026.gem-main.50/)，ACL Anthology 2026.gem-main.50）
- **Wang 等（ICLR 2026）发现"RL 会把污染痕迹藏起来"**：SFT 阶段可以被检测出来的污染，
  "even a brief GRPO training can markedly conceal contamination signals that most detection methods rely on"，
  机理是 PPO 式的重要性采样与裁剪目标；到最终阶段多数检测方法"perform near random guesses"。
  这意味着**用训练后的模型行为去反推数据是否被污染，在 RL 之后基本失效**。
  （[On The Fragility of Benchmark Contamination Detection in Reasoning Models](https://arxiv.org/abs/2510.02386)，arXiv:2510.02386，ICLR 2026）

所以对"边训边测是否导致过拟合"的完整回答是：
**看板能给出的最强结论是"没有看到过拟合自家题的迹象（方向相反，且两 run 一致）"；
"评测集是否被污染"这个问题，本看板在原理上无法回答，需要上面第 1~5 类数据。**

## 十一、三个可迁移的专业概念

### 概念 1：最小可检测变化（MDE，minimum detectable change）

- **定义**：一个测量工具本身的噪声有多大，决定了"多大的变化才值得当真"。若单次测量噪声是 σ，
  两次测量之差的标准误是 σ√2，95% 口径下 `MDE = 1.96·σ·√2 ≈ 2.77σ`。
  比 MDE 小的变化，你**看不见**——不是"没有变化"，是"这个尺子量不出来"。
  配套的两个坑：**必须先把趋势去掉再估 σ**（否则趋势会混进噪声）；
  **相邻差分会因负自相关而高估 σ**（要用残差，不要只用差分）。
- **本文数据里的体现**：DeepSWE 的 MDE 是 flash 6.43 分 / pro 4.56 分，In-house 是 1.68 / 1.55，
  相差 3~4 倍。全数据集最大的单步变化（DeepSWE/flash 第 10→11 步 −6.05 分）**刚好在 MDE 边缘**，
  而且它是 115 个变化里挑出来的最大值，多重比较后完全不显著。
- **可迁移的判断规则**：拿到任何"指标 A 掉了 X"的说法，先问两个数——**σ 是多少、比较了几次**。
  只有 `|Δ| > 2.77σ` **且** 这个 Δ 通过了该序列的多重比较校正，才值得写进结论。
  用同一把尺子衡量自己：结论里出现的每一个"涨了/跌了"，都要能说出对应的 MDE。

### 概念 2：自相关导致的"有效样本量缩水"

- **定义**：时间序列里相邻观测不独立时，n 个点携带的信息少于 n 个独立点。
  AR(1) 结构下 `n_eff = n·(1−ρ)/(1+ρ)`，ρ 是一阶自相关。
  ρ=0.3 时 20 个点只值 10.8 个点；ρ=0.5 时只值 6.7 个。不校正就会把显著性系统性算高。
  工程上三条常用替代：Newey-West（HAC）稳健标准误、块置换检验、或直接用 n_eff 重算自由度。
- **本文数据里的体现**：pro 的三条榜序列残差 ρ₁ = 0.25~0.32，n_eff 从 16~17 掉到 8.3~10.2（剩 52%~60%）。
  用它重算后 AutomationBench/pro 的趋势 p 值从 <1e-4 变成 0.0026（依然显著）。
  反过来，DeepSWE/flash 的 ρ₁ = −0.461（高低交替），朴素的 OLS 检验其实是**偏保守**的
  ——所以"考虑自相关"不等于"一律把显著性调低"，要看 ρ 的符号。
- **可迁移的判断规则**：任何"逐步/逐日/逐周"的序列，做显著性检验前先算 ρ₁。
  `|ρ₁| > 0.2` 就必须换用 n_eff 或 HAC；同时**同一批结论要多跑三种方法（n_eff / Newey-West / 分块置换）**，
  三种都过才写结论。本文的趋势结论三种方法都过，单步变化结论三种都不过。

### 概念 3：饱和曲线的参数不确定性与"什么时候该停"

- **定义**：给一条还在上升的曲线拟合"饱和平台"，模型有很强的形状假设。
  指数/Gompertz 在速率参数 c→0 时平台 a→∞，**用有限窗口的数据在数学上无法区分"接近平台"与"缓慢线性上升"**，
  这叫参数不可识别。判据要写死一个门槛（本文用"平台 CI 宽度 > 2 倍数据极差 ⇒ 不可识别"），
  并且必须报告**模型之间的预测分歧**，不能只报 AICc 最优的那个。
- **本文数据里的体现**：6 个榜序列里 5 个的平滑模型不可识别；`avg@n`/flash 的模型间平台跨度 9.3pp
  （是它自身 MDE 3.08pp 的 3 倍）。分段模型（唯一不需要形状假设的）在 6 个榜上都说"已经到平台"，
  而两个平滑模型说 flash 还有 8.4~9.8pp 空间、需要再走 28~38 步。
  **"还差多少步"这个问句的答案，在 −6 步到 +38 步之间摆动。**
- **可迁移的判断规则**：用外推模型回答"还要跑多久/还要投多少"时，交付物里必须同时出现三样东西：
  (1) 至少 3 个模型的平台预测并排；(2) 参数的 bootstrap 区间宽度；(3) 一个**不用外推**的参照量
  （本文是 MDE —— 如果剩余空间本身小于 MDE，那么"还有空间"这个判断无论如何都不可验证）。
  三样缺一，就把结论降级成"看不出"。

## 十二、术语速查

| 术语 | 一句话解释 |
|---|---|
| `avg@3` | 每道题采样 3 次、取平均通过率；三个离线榜都是这个口径 |
| `dynsam/avg@n` | 训练侧主指标：每道题采样 n（=16）次的平均通过率，量的是训练分布，不是固定测试集 |
| MDE | 最小可检测变化：这个尺子能分辨的最小分数差，本文用 `2.77 × σ_pt` |
| σ_pt | 单点测量噪声的标准差；本文用趋势残差的 SD 估计（不是相邻差分的 SD） |
| Theil–Sen 斜率 | 稳健趋势估计：所有点对斜率的中位数，对离群点不敏感 |
| n_eff | 有效样本量：扣掉自相关之后，n 个点实际等于几个独立点 |
| 置换检验 / 分块置换 | 不假设分布形态的显著性检验；分块版本保留自相关结构 |
| Holm-Bonferroni | 多重比较校正：同一组里比较 k 次时，最显著的 p 要小于 0.05/k |
| 饱和模型 | 假设曲线最终会走平（有平台）的拟合模型；本文用了四种 |
| 可识别 | 参数能被数据定下来。CI 特别宽就是不可识别的信号 |
| `piecewise_linear_plateau` | 分段线性到平台：先直线涨、到某一步之后变成常数，不需要假设曲线形状 |
| bootstrap | 反复重采样估参数的区间；本文用固定种子，结果可复现 |
| `cost/rate_per_s` | 成本速率（每秒烧的钱）= 机器数的读数；pro 5.71/s、flash 2.855/s，全程恒定 |
| `axis.walls` | 每一步**完成**的墙钟时刻；本文用它做按时间的对齐 |
| gap | 在线通过率 ×100 与榜分之差，衡量"在线读数离真实能力有多远" |
