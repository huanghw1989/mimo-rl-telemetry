# 训练 run 停止的读法 —— 以 mimo-v2.6-flash 的停止为例

> 独立收藏笔记。收藏日期 2026-09-19（北京时间）。
> 数据截至 2026-09-19 06:23 UTC：pro 第 23 步完成（第 24 步进行中）/ flash 第 30 步（已停止）。
> 外网来源同日用代理浏览器采集，清单在第六节。
> 本文与 `analysis/` 的 A2 系列互相独立：A2 是观测窗口的正式分析序列，
> 本文把这次事件沉淀成可搬走的读法，事件本身当案例用。

## 一、结论（先说人话）

1. **flash 的停止是一次刻意的、有序的收尾，不是崩溃，也不是卡死。**
   看板状态字段 `run.mode = "ended"`，事件流里有一个干净的 `end` 事件，
   最后一步（s30，09:04 北京时间完成）之后没有任何重启痕迹。
2. **它的机器没有被腾给 pro。** pro 的成本速率（每秒烧的钱）从第一天到 flash 停止后
   一直是 $5.71/秒，没有变过一分钱；两条线的 2:1 机器配比是从开局就固定的。
3. **数据能支持的唯一解释：小模型这一档的 RL 数据点已经采完**——
   主指标走平、离线评测不再上送、熵在涨但不转化，三个信号全齐（第四节）。
4. **官方没有说明动机**（公告栏无公告、罗福莉 X 自 9/17 后无新帖），社区也在问同样的问题。
   "做完了"和"计划中暂停（评测/发布/新一轮）"目前都成立。

## 二、知识 1：三种停止形态，两个字段就能区分

看板里一次训练停止，只有三种形态，全部可以从 `run.mode`（run 状态字段）
和事件流（`events`）尾部区分出来，不需要等官方说明：

| 形态 | `run.mode` | 事件流尾部 | 配套现象 |
| --- | --- | --- | --- |
| 正常训练 | `live` | `step`（步完成）事件持续 | — |
| 崩溃 / 故障停 | `live` | 出现 `restart`（重启）事件，步号回退或重复 | 公告栏通常有重启公告；步与步之间出现远超正常步时长的空档 |
| 干净收尾 | `ended` | 最后一个 `step` 之后只跟一个 `end`，**没有** `restart` | 无公告、无重启、收尾间隔有限 |

判断就两步：看 `run.mode` 是不是 `ended`，看事件流尾部是 `restart` 还是 `end`。

flash 本次三条证据：

- `status.json` 里 `run.mode = "ended"`，`run.end = 2026-09-19 10:22`（北京时间）；
- 最后一步 s30 在 09:04 正常完成，之后无 `restart`——此前 5 次故障
  （09-16、09-17 各 1 次，09-18 三次，全是 `restart` 事件）形态都和这次不同；
- s30 完成到 `end` 间隔 78 分钟，是有限短间隔。故障等修复按此前 5 次的形态
  会先留 `restart` 再等数小时；这次直接收尾。

**数据只能定停止的形态，定不了停止的动机**——这是用这类看板时最容易越界的一步。

## 三、知识 2：成本速率是机器数的读数（资源调配判定 + 规模对照）

**方法**：`cost/rate_per_s`（成本速率，每秒烧的钱）是机器数的直接读数——
同种机器每秒单价恒定，"多少台机器在烧钱"除单价就是这个数。
机器被腾走或加进来，这个数字会出现台阶式跳变。

**本次判定**：

| | pro | flash |
| --- | --- | --- |
| 成本速率 | $5.71/秒 | $2.855/秒 |
| 观测窗口（09-17 18:49 → 09-19 14:23，约 44 小时）内的变动 | **平，无一次跳变** | 平，到停止为止 |
| 折每小时 | $20,556 | $10,278 |
| pro : flash | **2.000 : 1**（精确到小数点后三位） | |

若 flash 的机器（约 $10.3k/小时）腾给 pro，pro 的速率应从 $5.71 跳到约 $7.6，
或当前步期望时长缩短约三分之一。两条都可直接验证，都没出现：
10:22 之后 pro 速率仍 $5.71/秒；pro 当前第 24 步已过 130 分钟、期望 225 分钟、
进度 58%，与前几步（197~228 分钟/步）同速。

对照：**pro 自己在变慢，不是变快**——前半程（s3–s10）平均每步 153 分钟，
后半程（s18–s22）202 分钟；原因是每步 token 从 s15–17 的 22.9~23.5 亿
涨到 s18–23 的 24.9~27.7 亿。算力被越来越难的题目吃掉，没有被重新分配。

### 2:1 的配比和模型规模对得上吗

2:1 从最早观测点（09-17 18:49）起就是这个数，媒体"36 小时约 108 万美元、
平均每小时 3 万美元"（量子位）和知乎拆解（09-17 深夜，pro $5.71/s、flash $2.86/s）
两个独立快照一致——**从开局就固定的调配**，与本次停止无关。

两条独立路径把 2:1 和模型规模对起来，都指向同一个数：

- **路径 1（每 token 成本）**：累计口径（到 09-19 06:23），pro 188.8 万美元 / 53.0B token、
  flash 85.4 万 / 81.4B。每 10 亿 token 成本 pro 3.56 万、flash 1.05 万，**差 3.4 倍**。
  MoE 模型每 token 的计算量正比于激活参数（总参数里真正参与该 token 计算的部分），
  同种硬件下每 token 成本比 ≈ 激活参数比。
- **路径 2（机器数 × 吞吐）**：机器比 2.0 ÷ 实测 token 吞吐比
  （后半程均值：pro 约 20.3 万 token/秒，flash 约 30.5 万，比约 0.67）≈ **3.0**。

合起来读作"**pro 的激活参数大约是 flash 的 3 倍**"（推断，前提是同种机器单位计算效率可比；
两条路径的差值是效率差的读数）。

参数量背景（证据强度分开）：

- 上一代公开：MiMo-V2.5-Pro 总参数 1T（代码 agent 方向）、MiMo-V2.5 总参数 310B
  （多模态方向），2026-04-28 开源（罗福莉 X 帖，官方一手）；
  MiMo-V2-Flash 总参数 309B / 激活 15B 的 MoE（官方技术报告 arXiv:2601.02780 摘要，官方一手）。
- v2.6 两条线的参数量**没有公布**（站点 about 只写 "coming soon"）；
  9/17 当天有"1T 参数 MiMo RL run"的社区报道流传（社区说法，官方未确认）。
- 若 v2.6-flash 激活仍是 15B 量级，pro 激活约 45~50B 对 1T 总量的 MoE 是合理量级（推断）。

### 两条线是同一套 recipe：scaling 曲线的两个点

知乎拆解（社区分析）把两条线配置逐项拉平对比过：**batch 同为 1568 prompts × 16 rollouts，
数据配比几乎相同（agentic 约 47%、code 约 36%），学习率同为 3e-6，同一套 23 个执行 harness**
——只有模型大小和机器数不同。

若如此，两条线本质是**同一条 RL scaling 曲线的两个点**：罗福莉宣布的研究问题是
"how far can RL scale"，scaling 曲线至少两个点才画得出来，并行跑最省时间。
这是推断不是官方说法——Dinghuai Zhang 在 X 回复里问过同样的问题，官方没有回答
（回复区在登录墙内，此句转引自 explainx 的整理）。

## 四、知识 3："这个规模的数据点采完了"的三信号

看一个 run 值不值得继续训，别只看主指标斜率，把三个信号合起来看：

**信号 1：主指标走平。** `dynsam/avg@n`（每道题采 n 次的平均通过率，看板主指标）
flash 最后 6 步：0.641 / 0.638 / 0.644 / 0.643 / 0.662 / 0.644，
6 步净涨 +0.0027；前半程每步能涨 +0.005~0.01，末段是 ±0.02 的震荡、重心不动。

**信号 2：离线评测不再上送。** DeepSWE（长程软件工程任务离线评测）flash 最后一条是
**第 25 步（64.9）**；s18–s25 八步一直在 59.6~65.8 之间震荡没有新高度；
s26–s30 的 checkpoint 没送评——评测节奏跟着训练一起停了，这本身就是个动作。

**信号 3：熵在涨但不转化。** `actor/entropy_loss`（策略熵，探索的宽度）
s20–s30 从 0.4343 走到 0.4706（10 个间隔 6 个向上），同期通过率是信号 1 的平。
探索变宽了，但没挖到新能力。

三条合起来就是"数据点采完"的形态：flash 用 30 步、81.4B token、$85.4 万、
avg@n 0.514 → 0.644（+13.0 个百分点）、DeepSWE 48.67 → 64.9，
把"这个规模上 RL 还能再榨多少"回答了——之后继续训的边际收益接近零，
停下来是理性的。（注意身份：三个信号是事实，"采完"是对信号的解释，属于推断。）

**对照 pro（要诚实）**：pro 也在放缓。它的 DeepSWE 到 s18 还在涨
（s13→s18：63.27 → 67.46，5 步 +4.2），但在线主指标最后 2 步（s22–s23）
已从 s20–s21 的 0.642~0.643 回落 2 个百分点到 0.622，且离线评测同样停在 s18
（训练到 23 步）。"flash 平了、pro 还在涨"只成立到 s21 为止——
两条线在末段实际都在放缓，差别是 pro 回落幅度小。
pro 是否到顶，同样用三信号看：目前一个半（评测滞后、主指标放缓，熵在涨但在转化）。

**可迁移的判断规则**：三信号全到 → run 到该规模上限，"停下来换更大的"比"继续烧"理性；
只到一两个 → 多半是波动，继续跑。

## 八、编注：后来一轮独立复核带来的两点补充（2026-09-19 晚）

这一节来自 `notes/13-异步管线与机时账.md`（独立的 `pipeline_report.ts`），**补充而不是推翻**本文。

1. **本文第三节"成本速率无一次跳变"成立，但同期资源确实动过一次。**
   复核发现 pro 的 `env/active`（并发活跃沙箱数）在**第 23 步一步内从 23,419 跳到 37,888（+61.8%）**，
   而 `rate_per_s` 保持 $5.71/秒不变。也就是说"在烧钱的机器数没变"这一条仍然成立，
   但**编排层的沙箱并发配置改了** —— 这两件事可以分开，看板上只有前者有价格标签。
   所以"速率平 = 资源没动"这个推论要收紧成"速率平 = 计费口径的机器数没动"。

2. **"沙箱翻台率"那种读法要改口径。** 有一处流行读法拿 `env/total_setup ÷ env/active` 算翻台率
   （pro 第 10 步约 14.3、flash 第 15 步约 14.2）。复核发现 `env/total_setup` 是**自上次重启以来的累计启动数**
   —— 每到重启那一步就掉回与 `active` 同量级再往上加（pro 第 11/15/17/23 步、flash 第 16/25/28 步都能看到归零）。
   所以那个 14 的含义是"这一段里每个沙箱位子平均服务过约 14 条轨迹"，
   **不是"每步翻台 14 次"**；除以段内步数才是每步约 2 次。相关的指标解读已经改正。

补充一条同源的更正：本文说 flash 停止后计费表不再增长 —— 复核确认它**精确冻结**：
`cost.so_far ÷ rate = 299,140.0 秒`，与 `end − run_start` 完全相等，停止后 6.6 小时内没有继续计费。

## 术语速查

| 术语 | 人话 |
| --- | --- |
| `run.mode` | run 的状态字段：`live`（在跑）/ `ended`（已收尾） |
| `end` / `restart` 事件 | 事件流尾部两类停止事件：前者干净收尾，后者崩溃后重启 |
| 成本速率 `cost/rate_per_s` | 每秒烧的钱；同种机器下 = 机器数 × 单机价，可当机器数读数 |
| `dynsam/avg@n` | 每道题采 n 次的平均通过率，看板主指标 |
| `actor/entropy_loss` | 策略熵：探索的宽度；持续涨而成功率不跟 = 白花钱的探索 |
| `penalty/signed/neg_mass_added` | 惩罚分支往负侧加的优势质量；站点未解释用途 |
| 激活参数 | MoE 总参数里真正参与每个 token 计算的部分；每 token 计算量正比于它 |
| MFU（模型算力利用率） | 机器算力的实际利用程度；第三节两条反推路径的差值部分来自它 |
