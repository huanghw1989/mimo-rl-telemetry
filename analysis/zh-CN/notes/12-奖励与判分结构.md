# 奖励信号与判分结构：分数是判出来的，还是模型自己涨的

> 材料身份：**我方实测**。数据来自本地遥测 `data/store/`，本文所有数字由脚本 `src/reward_report.ts` 从原始 JSON 复算，脚本内没有硬编码任何结论数字；每个数字都能在 `analysis/zh-CN/numbers/A3-reward-numbers.json` 里按 key 找到。涉及外部论文的部分单独标 **【外部文献】**。
> 数据窗口：**pro 第 1~24 步、flash 第 1~30 步**（`axis.json`；pro 最后一次墙钟 2026-09-19 07:52Z，flash 2026-09-19 01:04Z）。
> 样本量：**全程只有 24 / 30 个点**。本文所有相关都带 n 与 p 值；水平相关、一阶差分相关、去线性趋势残差相关三个口径同时给。凡 p>0.05 一律写"不显著"，不用趋势词描述偶然波动。
> **本文与 `notes/05`（恒等式核查）、`notes/06`（口径陷阱）、`notes/08`（生成长度）、`notes/09`（长度相关性）不重叠**：那些讲长度和口径，本文只讲奖励信号与判分流水线。唯一例外是第七节的惩罚项恒等式，需要引用 `notes/05` 已确认的结论作为对照。

## 一、摘要：六条结论

1. 【我方实测】**奖励的"上限"从第一步就被钉死了，变的是中位数和下限，不是上限。** 两个 run 的 `critic/score/max`（本步轨迹最高得分）**24/24 与 30/30 步全部精确等于 1.000**，只有一个取值。同一时期 `critic/score/mean` 分别从 0.5522 涨到 0.5963（pro，r=0.904，p=1.4e-9）和从 0.5167 涨到 0.6005（flash，r=0.939，p=1.8e-14）。所以"奖励越来越集中在少数样本上（max 抬升）"**不成立**——max 没有再抬升的空间；真实变化是整条分布的中段上移。而 min 的走向两个 run **相反**：pro 的最差轨迹首末在改善（mean−min 从 1.2593 收到 0.7384，但中间第 14、22 步两次触底 −0.8），flash 的最差轨迹在恶化（mean−min 从 1.3139 扩到 1.4005，r=0.523，p=0.003，贴地板 −0.8 的步数占比 33%）。

2. 【我方实测】**可训练池确实在收缩，但两个 run 差一个数量级；而且它已经把 avg@n 的增速吃掉了一大块。** 用 `avg@n = p1 + M·m` 分解（p1 = 全对占比，M = 1−全错−全对 = 可训练池占比，m = 池内平均通过率）：pro 的 M 从 0.6759 降到 0.6545（−0.0213），flash 从 0.7188 降到 0.5528（**−0.1659**）。逐项分解 Δavg@n：pro 的 +0.0318 = 全对率贡献 +0.0236 − 池收缩 −0.0125 + 池内提升 +0.0207；flash 的 +0.1298 = +0.1700 − 0.0983 + 0.0582（残差 0）。**"池子收缩"不是增速放缓的原因，它是被减掉的那一项；真正撑住成绩的是池内通过率和全对率的上升。** 另外 pro 的 avg@n 在**第 20 步见顶 0.6431 后回落**到第 24 步的 0.5964，后 11 个增量的均值为 **−0.0025**，前半段是 +0.0049。

3. 【我方实测】**判分侧没有变松的证据，反而在几个内部读数上系统性收紧。** 判分漏斗入口/出口都是平的：`groups_total` pro 1811（均值）r=−0.192（p=0.37），flash 1750（均值）r=−0.004（p=0.98）；`groups_judged` pro 794 r=−0.094（p=0.66）。失败率没有上升（`select_groups_failed / groups_attempted` pro 3.5%→4.2%，r=0.109，p=0.61）。而判分自己的**档位绝对分在下降**：五个维度 A/B/E/P/S 的等权均值 pro 从 4.4051 降到 4.2902（r=−0.874，p=2.5e-8），flash 从 4.3919 降到 4.3108（r=−0.482，p=0.007）；`select_factor_mean`（判分后处理乘子）pro 从 0.8319 降到 0.8033（r=−0.767，p=1.2e-5），`select_renorm_k_mean` 反向从 1.1852 升到 1.2179（r=0.854，p=1.1e-7）。

4. 【我方实测】**`select_above_gold_share`（判分认为"超过参考解"的比例）并没有上升。** pro 从 0.3185 到 0.3182（r=−0.003，p=0.99，**完全持平**）；flash 从 0.3018 到 0.3261（r=0.377，p=0.040，但一阶差分 r=−0.341，p=0.071 不显著，去趋势 r=−0.058，p=0.76）。也就是说"above_gold 上升"这个前提在本数据里**对 pro 是错的、对 flash 只有弱到站不住的上升**。同时判分探针不一致率 `select_probe_disagree_rate` 在 **0.59~0.61 的高位且上升**（pro 首0.5748→末0.6331，r=0.687，p=2.1e-4；flash 首0.5460→末0.6018，r=0.704，p=1.4e-5）——**外网那个"判分器不一致率到 60% 且在上升"的读数，在本数据里能找到对应指标，且方向与量级都对得上**。

5. 【我方实测】**"疑似作弊尝试率"的上升是真的，但它和成绩同向只是共同趋势。** `select_hack_attempt_rate` pro 0.3833→0.4228（r=0.706，p=1.2e-4），flash 0.3824→0.4985（r=0.788，p=2.4e-7）。**独立复核结论：一阶差分相关不显著**（pro r=0.043，p=0.85；flash r=−0.242，p=0.21），去趋势残差相关也不显著（pro r=0.116，p=0.59；flash r=−0.185，p=0.33）。而同期**计数**几乎不动（pro 4563→3830，r=0.103，p=0.63；flash 4298→4953，r=0.334，p=0.071），说明率上升主要来自分母（判完组数）而非分子。

6. 【我方实测】**判分不是整步时间的瓶颈，但"判一组"这件事本身极贵。** 整步墙钟只有三个桶（生成 / 训练 / 残差），生成+训练占 **97.9%（pro）/97.2%（flash）**，判分根本没有独立时间桶——它是与生成重叠跑的。但按 `groups_judged × time_total_sec_mean` 估，判分每步要消耗 **4.46e5（pro）/4.47e5（flash）秒**的判分机时；判一组平均 **559 秒（pro）/569 秒（flash）**，而同一批候选组分到的整步墙钟预算只有 **5.77 秒（pro）/4.75 秒（flash）**——**判一组的墙钟是整步摊给每个候选组的 106 倍（pro）/127 倍（flash）**。分摊到被训练的 rollout 上，判分是 **17.8 秒/条**（两个 run 都是）。环境准备（`time_pod_setup_sec_mean` 14.6/15.2 秒）只占判分耗时的 **2.63% / 2.68%**。

| 依赖 | **零第三方依赖**。Pearson / Spearman（并列取平均秩）/ OLS / 一阶差分 / 去趋势残差 / t 检验 p 值（用自实现的正则化不完全 Beta 函数，非正态近似）全部脚本内实现 |

| 恒等式判定 | `exact` = 最大绝对差 ≤ 给定容差（多数为 0）；`near` = 最大相对差 ≤ 1% 或最大绝对差 ≤ 指定绝对门槛；`broken` = 两者都超；`not-comparable` = 一侧无数据 |

### 2.3 必须先说清的五处口径问题

1. **`penalty/signed/pos_mass_added` 这个 tag 不存在**。任务清单里写的 `pos_mass_added` 在两个 run 里都是 0 个值；真实存在的是 `penalty/signed/pos_mass_removed`（pro 24 步全有值，flash 只有第 1~20 步）。下文一律用 `pos_mass_removed`。
2. **`critic/rewards/*` 与 `critic/score/*` 是同一组数**（mean/min/max 三层最大绝对差都是 0），`critic/returns/*` 与 `critic/advantages/*` 同理（mean/min 也是 0）。所以"奖励有四个指标"是错觉，实际只有两个独立量：**得分**和**优势**。
3. **`critic/advantages/mean` 是一个在 0 附近、由构造决定的量**。它的绝对值只有 `critic/advantages/min` 绝对值的 **0.36%~2.8%**（pro 首 0.0036、flash 末 0.0235）。拿它的走向说"优势在衰减"是无效读法，见第八节。
4. **`train/passrate/passrate_0_ratio` 与 `dynsam/passrate/zero` 不是一回事**。前者 pro 从 0.0092 涨到 0.0389、flash 从 0.0091 涨到 0.0830；后者 pro 从 0.1462 到 0.1440、flash 从 0.1605 到 0.1564。两者分母不同（前者是"进了训练 batch 的轨迹"，后者是"被测量的候选池"），不能互相换算，也不能用前者说"全错率躺着不动"或"全错率涨了 4 倍"而不说清分母。
5. **flash 有一批 tag 在中间步之后停止上报**，不是变成 0：`groups_attempted`、`end2end_success_rate`、`dev_neg_turns`、`pos_scale_clamped` 都是**第 1~19 步**有值、之后是 null；`pos_mass_removed`、`pos_scale` 是**第 1~20 步**。而 `pass1_success_rate`、`groups_judged`、`groups_total` 是满 30 步的。任何 flash 的"全程均值"都要说明是按多少步算的。

## 三、奖励信号的分布形状

**结论**：上限被钉死（max≡1），中段持续上移，下限两个 run 走向相反（pro 收紧、flash 扩张）。整体抬升，不是向少数样本集中。

**大白话**：如果把这一批轨迹的得分排序，最高分那条从第一步起就是满分 1.0，之后再没变过——奖励函数有上限（上限就是 1，且 `critic/score/min` 的下界是 −0.8，两个 run 全程都没突破过）。所以"模型越来越会刷高分"这件事只可能体现在平均分上升。下限那头两个 run 走向相反：pro 的首末最低分是往上收的（−0.71 → −0.14，但中间在第 14、22 步两次触底 −0.8），flash 的最低分则越掉越深（30 步里有 10 步正好等于 −0.8）。

## 四、样本池在收缩吗

**结论**：在收缩，但 pro 几乎没动（−2.1 个百分点），flash 大幅收缩（−16.6 个百分点）；池收缩**已经在拖 avg@n 的后腿**，而且它不是增速放缓的原因，它是被减掉的项。

**大白话**：动态采样（dynamic sampling）的规则是把"全对"和"全错"的题丢掉——全对的题不提供梯度，全错的题也提供不了有用的对比。所以模型越强，全对率越高，可训练的池子就越小。这件事在 flash 上非常明显：可训练池占比从 71.9% 掉到 55.3%，少了近六分之一。但成绩还是在涨，因为池子里剩下那些题的通过率同时在涨，而且全对率本身也是成绩的一部分。

### 证据表 C：池子指标（n = 24 / 30）

| 指标 | pro 首 → 末 | flash 首 → 末 |
|---|---|---|
| `dynsam/passrate/zero`（全错占比） | 0.1462 → 0.1440 | 0.1605 → 0.1564 |
| `dynsam/passrate/one`（全对占比） | 0.1779 → 0.2014 | 0.1208 → 0.2907 |
| **可训练池 M = 1 − zero − one** | **0.6759 → 0.6545（−0.0213）** | **0.7188 → 0.5528（−0.1659）** |
| 池内平均通过率 m（由 `avg@n = p1 + M·m` 反解） | 0.5723 → 0.6035 | 0.5467 → 0.6382 |
| `dynsam/avg@n` | 0.5647 → 0.5964 | 0.5137 → 0.6435 |
| `dynsam/num_measurable` | 4040 → 2790 | 3642 → 3553 |
| `dynsam/num_target` | 恒 1568 | 恒 1568 |
| `train/verdicts/trained` | **恒 25088** | **恒 25088** |

### 证据表 D：把"池子收缩"从 avg@n 增速里剥出来

分解式：`Δavg@n = Δp1 + m̄·ΔM + M̄·Δm + 交互残差`（m̄、M̄ 取首末均值）

| 分量 | pro | flash | 含义 |
|---|---|---|---|
| Δp1（全对率上升直接贡献） | **+0.0236** | **+0.1700** | 原本做对一半的题变成次次做对 |
| m̄·ΔM（池子收缩的扣除） | **−0.0125** | **−0.0983** | 可训练题变少，纯拖累 |
| M̄·Δm（池内通过率提升） | +0.0207 | +0.0582 | 剩下那些题做得更好了 |
| 交互残差 | 0.0000 | 0.0000 | 分解闭合 |
| **合计 = Δavg@n** | **+0.0318** | **+0.1298** | — |

**"这与 avg@n 的增速放缓是同一件事吗？"——不是同一件事，但有因果关系方向上的区别。**
- 池收缩是**已经计入**的减项（−0.0125 / −0.0983），它不会让 avg@n"放缓"，它直接让 avg@n 更低。
- 增速放缓是另一个现象：pro 的 avg@n 在第 20 步见顶 0.6431 后回落到 0.5964（−0.0467，−7.3%），24 个增量里前 12 个均值 +0.0049、后 11 个均值 **−0.0025**（增量对序号 r=−0.305，p=0.16，**不显著**）；flash 前 15 个增量 +0.0054、后 14 个 +0.0035（r=−0.076，p=0.69，**不显著**）。**两个 run 都没有统计上站得住的"增速放缓"**，pro 的表现更像"见顶后回落"而不是"斜率变小"。
- 真正的共同原因更可能是：**全对率上升 → 池子收缩 → 剩下可学的题变少 → avg@n 的上升空间被自己吃掉**。这在 flash 上被量化为：全对率贡献的 +0.1700 里，有 58% 被池收缩（−0.0983）抵消掉。

### 关于 `num_measurable` 与 `num_target`（一处对不上）

`dynsam/num_target` 恒为 1568，`train/verdicts/trained` 恒为 25088 = 1568 × 16（脚本核对 `trained/num_target` 在所有步恒等于 16，变异系数 0）。所以每步固定训练 **1568 题 × 16 次采样**。但 `dynsam/num_measurable`（可测量的题数）pro 从 4040 降到 2790（−31%，对步号 r=0.007，p=0.97，**无趋势**），flash 从 3642 到 3553。它与 `avg@n` 的相关 pro r=−0.079（p=0.71）、flash r=0.327（p=0.078），**都不显著**。
**结论：`num_measurable` 不是"可训练池大小"的计数版本，它与池占比 M 也不同步（M 在 flash 上掉了 16.6 个百分点，num_measurable 基本没动）。看板没有给它的分母/口径，我不做进一步推断。** 这是本文明确标注"对不上"的第一处。

## 五、判分侧在变松还是变紧

**结论**：**流量端没有任何松紧变化**（入口、出口、失败率、端到端成功率全部平的）；**判分内部读数在向"更紧 + 分歧更大"漂移**（档位绝对分下降、后处理乘子下降/重归一化上升、探针不一致率上升）；但**"超过参考解"的比例没有上升**。所以"成绩是判分放水放出来的"这个假说在本数据里**没有支持证据**，同时"模型真的超过了参考解"也**没有证据**——两者都不能用这份数据确立。

**大白话**：判分流程是个漏斗：候选组 → 一半直接不判（`routed/off`）→ 另一半分给两条判分路（`select_v4` 有参考解、`select_v4_nogold` 没有）→ 判完拿分。这个漏斗的形状 24 步/30 步基本没变。但判分给分的那把尺子在动：五个维度的绝对分在往下走，后处理里把分数往下乘的因子越来越大、补偿性的重归一化系数也越来越大。同时，判分内部两套探针互相打架的比例从 55% 涨到 60% 以上。

## 六、判分成本："判代码比跑代码还贵"能不能站住

**结论**：判分**不是整步时间的瓶颈**（它和生成重叠跑，没有独立时间桶），但**"判一组"这件事本身极贵**：单组判分 9~11 分钟，而整步摊给每个候选组的墙钟预算只有 5 秒上下，差约两个数量级（106 倍）。"判代码比跑代码还贵"这句话**在本数据里能验证到"判分单价远高于同期的其余流水线环节"，但无法用美元定价验证**——缺的东西很具体。

**大白话**：一步训练的总墙钟被拆成"生成"和"训练"两块，加起来占 97%~98%，剩下的残差只有 3 分钟出头。也就是说判分不在这一步的关键路径上，它是后台异步跑的。但把判分的工作量加起来看：一步要判 800 个组左右，每组平均要跑 9 分多钟的判分墙钟，合起来是 44.6 万秒的判分机时。这一步的全部墙钟只有 10077 秒。**要在一个步长内把这些活干完，需要至少 46 路判分并发（pro）/ 57 路（flash）；观测到的在飞判分组数是 92 / 108，是需要的两倍左右，所以判分有余量，不紧张。**

| 实测 `judge_pool_in_flight`（在飞判分组） | 均值 **92** | 均值 **108** |
| 判分机时 ÷ `train/verdicts/trained` | **17.79 秒/条训练轨迹** | **17.82 秒/条** |
| `timing_s/step` ÷ `groups_total`（每组摊到的整步预算） | 均值 **5.77 秒** | 均值 **4.75 秒** |
| 单组判分 ÷ 每组整步预算 | 均值 **105.8 倍** | 均值 **126.6 倍** |
| `select_pass_turns_mean` | 49.2 → 60.9，r=0.487, p=0.016 | 50.2 → 72.9，r=0.682, p=3.4e-5 |

### "判代码比跑代码还贵"能不能站住

**能站住的部分（我方实测）**：
- **判分单价高到必须靠并行摊平**：判一组要 559 秒，而整步给每个候选组的墙钟预算只有 5.77 秒，**差 106 倍**。也就是说同样的一个"候选组"，判它一次的墙钟是这一步为它预留的全部时间的百倍量级。这条**量化了"判分贵"这个直觉**。
- **贵不在环境准备**：`time_pod_setup_sec_mean` 只占判分耗时的 2.6%，所以"判分贵"不是起沙箱慢，是判分逻辑本身在跑（第一遍判分占 97.3%）。
- **pass 2 完全没启用**（`time_pass2_sec_mean` 恒 0，`judge_pass2_attempts` 恒 0，`pass2_success_rate` 恒 1.0 是空值），所以"两遍判分贵一倍"这种说法在本轮不成立。

**不能站住的部分（缺什么）**：
1. **没有美元的分子**。`cost = rate_per_s × (now − run_start)`（`notes/05` 已确认）只给总成本，看板没有判分机队与训练机队各自的 `rate_per_s`，所以"判分花掉的钱 vs 生成+训练花掉的钱"**无法结算**。
2. **判分没有独立时间桶**。`timing_s/*` 只有 `step` / `outer_gen` / `trainer_ops` 三个键，判分被隐藏在 `outer_gen` 的重叠里，无法从墙钟直接切出"判分占了百分之几"。
3. **没有单条 rollout 的生成墙钟**。要比较"判一条 vs 生成一条"的单价，需要"每条轨迹的生成耗时"，看板只给 `ctx_response_length/mean`（约 6.8 万~14.3 万 token，见 `notes/08`）和 `dynsam/agg_turn/mean`（每步平均轮数），没有每轮延迟，因此无法换算成秒。
4. **一个能算的替代口径**：按"每条训练轨迹摊到的判分机时"计，两个 run 都是 **17.8 秒/条**——这是本数据能给出的最接近"判分单价"的数字，但它仍是机时不是钱。

**结论**：**"判代码比跑代码还贵"在本数据里既不能被证实也不能被否证**。数据支持"判分是这条流水线里单件耗时最长的环节（单组 9~11 分钟，是本步全部墙钟的 1/18）"，但不支持任何美元层面的比较。这是本文第三处明确标注"缺什么"的地方。

## 七、优势缩放与惩罚：哪些是恒等式，哪些是真信号

**结论**：`penalty/action/*` 整组**从未触发**（3 个恒 0 + 1 个恒 1）；`penalty/signed/*` 一直在动但幅度极小（正侧偏离 1 不超过 0.31%，负侧最多 2.9%）；`pre == post` 是**精确恒等式**（惩罚走的是"按比例缩放 + 重归一化"，总量守恒是设计出来的）。真正称得上信号的只有 **flash 第 19~24 步和最后一步的负侧爆发**。

**大白话**：惩罚模块分两条路。一条叫 action（对 advantage 做加减或乘除），**它一次都没走**。另一条叫 signed（把 advantage 按正负拆开，各自缩放再归一化回去），它一直在轻微动作：正侧被压一点点、负侧被加一点点，加完之后做一次重归一化把总量还原——所以"惩罚前总量"和"惩罚后总量"逐点完全相等。这不是"惩罚没生效"，而是**总量守恒是设计目标**（`insights.json` 的 `penalty-redistributes` 已指出这一点，本节给出量化）。

## 八、熵上升、优势下降、成绩上升，三者同时成立

**结论**：三个观察都成立且都能复算，但**"优势下降"这个说法本身口径有问题**——`critic/advantages/mean` 是一个由构造决定的近零量，它的走向不携带"信号强弱"的信息。真正同时成立的图景是：**通过率上升 → 全对率上升 → 可训练池收缩 → 剩下的训练信号集中在"还做不够好"的那部分 → 负优势侧被推得更深、策略在这些位置上继续探索 → 熵上升。**

**大白话**：这三件事不矛盾，因为它们是三把不同的尺子量的：
- 熵量的是"模型输出有多不确定"。它涨，说明模型没有变得更死板。
- 优势的**均值**几乎恒等于 0（组内减基线之后本来就该是这样），它从 −0.003 漂到 −0.004 是小数点后的漂移；**优势的分布**才是信号，而 flash 的负端明显变深（min 从 −1.21 到 −1.67）。
- 通过率量的是"题做对没有"。它涨，说明模型在简单/中等题上更稳。
三件事同时成立，意味着**模型在简单题上变得更确定（全对率涨），同时在没有完全做对的题上继续探索（熵涨）**。

### 证据表 I：三个观察的量化

|---|---|---|---|
| `actor/entropy_loss` 上行 | 0.3953 → 0.4437 | 0.4133 → 0.4706 | pro r=0.885, p=9.3e-9；flash r=0.948, p=1.7e-15 |
| `dynsam/avg@n` 上行 | 0.5647 → 0.5964（第 20 步见顶 0.6431） | 0.5137 → 0.6435 | pro r=0.833, p=4.3e-7；flash r=0.970, p=1.2e-18 |

**为什么熵上升、优势下降、成绩却上升——五条机制，各自的证据强度**：

1. **【我方实测，强度高】"优势均值下降"是个口径假象，不是信号衰减。** `critic/advantages/mean` 的绝对值只有 `critic/advantages/min` 绝对值的 0.14%~2.8%。组内减基线的构造决定了全局优势均值必须接近 0；它的小数点后漂移可以由"负端尾巴变深而正端被封顶"完全解释：`critic/advantages/max` 被钉在 1.08~1.33（两 run 都不显著），而 `critic/advantages/min` 在 flash 上从 −1.21 掉到 −1.67。**用 mean 判"优势在衰减"是错的，应该看 min/max 的展布。**
2. **【我方实测 + 外部文献，强度中】组内标准化会把"全对/全错"样本的优势清零，于是可训练池收缩本身就是"优势总量变稀"的机制。** 全对率 flash 从 12.1% 涨到 29.1%，池子少了 16.6 个百分点。这与 **【外部文献】Dr. GRPO**（Liu et al., *Understanding R1-Zero-Like Training: A Critical Perspective*, [arXiv:2503.20783](https://arxiv.org/abs/2503.20783)）指出的"GRPO 的标准化项引入了优化偏置"是同一族问题的两面：组内基线/标准差归一化使得"越接近全对/全错的组，信号越弱"，而动态采样正是要把这些组丢掉。
3. **【外部文献 + 我方实测】本数据处在"熵没有塌缩"的区间，因此不能用主流的"熵塌缩 → 性能饱和"叙事来读它。** **【外部文献】Cui et al., *The Entropy Mechanism of Reinforcement Learning for Reasoning Language Models*, [arXiv:2505.22617](https://arxiv.org/abs/2505.22617)** 给出的经验律是 `R = −a·e^H + b`，即"性能是从策略熵里换来的"，观测到的常态是**熵随训练下降、性能随之上行**。**本数据的熵是上行的（pro +0.0484，flash +0.0573），与这条经验律的符号相反**——也就是说这一轮**没有进入熵塌缩区**，`actor/entropy_loss` 在这一段不是性能的上限约束。**这既是对该论文的"局部反例"，也提示它的经验律描述的是更后段的行为。**
4. **【外部文献 + 我方实测】成绩上升主要来自"锐化"而不是"获得新能力"。** **【外部文献】Yue et al., *Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?*, [arXiv:2504.13837](https://arxiv.org/abs/2504.13837)**（NeurIPS 2025 Oral）用大 k 的 pass@k 证明 RLVR 主要是在**锐化基座模型已经会的能力**，而不是获得基座没有的推理模式；在小的 k 上 RL 模型赢，大的 k 上基座模型更高。**本数据的对应证据**：全对率涨幅远大于平均通过率涨幅（graduation 效应），且 `above_gold_share` 完全持平（pro）——"把做对一半的题变成次次做对"与"锐化"一致，而"超过参考解"没有发生。
5. **【外部文献】熵升高在 RLVR 里是需要主动管理的对象，而不是单纯的好事或坏事。** **【外部文献】DAPO**（Yu et al., *DAPO: An Open-Source LLM Reinforcement Learning System at Scale*, [arXiv:2503.14476](https://arxiv.org/abs/2503.14476)）用 clip-higher 来避免熵塌缩，其动机正是"熵太低会让策略失去探索"。**本数据里熵上升 + 通过率上升，按该论文的判断属于"探索有产出"的那一类**，与 `content/metrics.json` 里 `actor/entropy_loss` 条目给出的读法一致（"熵涨、成功率也涨，是探索有产出"）。

**一处必须说清的方法学限制**：`entropy vs avg@n` 的**去趋势残差相关在两个 run 都是显著为负**（pro −0.620，p=0.0012；flash −0.395，p=0.031）。也就是说**去掉共同的时间趋势之后，"熵涨得多的那几步，通过率倾向于涨得更少"**。所以"熵与成绩同向"这个读法只在水平口径成立，**在去趋势口径下是反的**。这与 `notes/09` 在生成长度上发现的模式（水平正相关、差分转负）是同一类现象：**共同趋势制造的伪相关**。任何"熵和成绩互为因果"的说法在本数据上都不成立。

## 九、判分 harness 与版本切换

**结论**：**这份数据里不存在 grader harness 的版本切换。** 任务前提（"`harness-<X>` 有多个代号、哪些在什么时候出现/消失"）在数据层面**被推翻**：`penalty/stage_credit_group/harness/harness-A..D` 是**四个并行的判分分片**，不是四个版本；`harness-E..U` 只有 tag 名、**从来没有数据**；`tags.json` 的 `versions` 是**看板标签集版本**，不是训练器或判分器版本。唯一真实的结构性变化是 pro 第 15 步移除 cyber 数据集（训练侧少一个 harness 分片）。

**大白话**：要判断"是分片还是版本"，有个很硬的检验：如果是分片，同一时刻各分片的量应该**相加等于全局**，而且各分片的占比应该大致稳定；如果是版本，同一时刻只应该有一个版本在跑（或新旧版本此消彼长）。数据给的答案非常干净——**A~D 四个分片的 `groups_attempted` 逐点相加精确等于全局，最大绝对差 0**，四家占比全程稳定（pro 均值 0.231 / 0.256 / 0.260 / 0.252），没有任何一家消失或新出现。

## 十一、四个可迁移的专业概念

### 概念 1：动态采样的样本池收缩（trainable-pool shrinkage）

**定义**：在组相对优势（group-relative advantage）的 RLVR 里，一个 prompt 的 n 次采样如果**全对**或**全错**，组内奖励没有方差，优势被归一化后全是 0，这条样本不产生梯度。动态采样（dynamic sampling）因此主动丢掉这两类 prompt，只保留"做对一部分"的 prompt。**模型越强，全对率越高，可训练池就越小。**

**本文数据里的体现**：定义 `M = 1 − p0 − p1`（p0 = `dynsam/passrate/zero`，p1 = `dynsam/passrate/one`）。pro 的 M 从 0.6759 到 0.6545（−2.1pp），flash 从 0.7188 到 0.5528（**−16.6pp**）。用 `Δavg@n = Δp1 + m̄·ΔM + M̄·Δm` 分解，池收缩项对两个 run 都是负的（−0.0125 / −0.0983），在 flash 上吃掉了全对率贡献的 58%。

**可迁移判断规则**：看到 avg@n 或 pass@1 上升时，**先算 M 和它的变化**。如果 M 在快速下降，那么"成绩上升"里有一部分是**记账效应**（全对率本身进了平均通过率的分子），而"还能继续涨多久"取决于 M 还剩多少。**M 接近 0 时，平均通过率会趋近 1 但训练信号会先枯竭**——这时看板上应该出现的是 passrate 类指标上升、advantage/entropy 类指标变稀，而不是梯度爆炸。本文 pro 第 20 步后的 avg@n 回落与 M 已降到 0.65 同时发生，是这一规则的候选案例（因果未证）。

### 概念 2：判分器不一致率（probe disagreement）的观测口径

**定义**：当一个判分任务由多套判定路径（探针 / 多轮复核）共同决定时，"探针之间结论不一致的比例"衡量的是**判分自身的确定度**，而不是模型的正确率。它天然会偏高——因为任务本身可能有多种合理解法。

**本文数据里的体现**：`select_probe_disagree_rate` 在两个 run 都是 **0.586~0.606 的高位**且显著上行（pro r=0.687, p=2.1e-4；flash r=0.704, p=1.4e-5）。同一时间线上，"更接近确实出问题"的三个计数**反向下降**：`select_r2_flagged / groups_judged` pro 0.321→0.208（r=−0.743）、flash 0.313→0.220（r=−0.706）；`select_process_severe / groups_judged` flash 0.0533→0.0188（r=−0.545, p=0.002）。也就是说**"分歧变多"与"确认出错变少"同时发生**。

**可迁移判断规则**：见到"判分不一致率 60% 且在升"这类读数，不要直接读成"判分崩了"。三步核：(1) 找同期**需要人工/多轮复核才能确认的**计数（`*_flagged`、`*_rejected`、`*_severe`），看它们是否同向；(2) 如果分歧升而确认错误降，说明判分器在第一轮遇到更多边界样本、但复核机制把它们挡住了——这是"任务变难"而不是"判分变坏"；(3) 只有"分歧率升 + 确认错误率也升"才构成判分质量恶化的证据。**另外必须区分**：这类率的分母（判完组数）本身在缩小，率上升可能纯由分母造成（本文 `select_hack_attempt_rate` 就是这种情况）。

### 概念 3：advantage 归一化对熵的影响（组内基线让 advantage 均值恒为零）

**定义**：GRPO/DAPO 这一族算法在组（同一 prompt 的 n 次采样）内减均值、除以标准差得到 advantage。**"减均值"这一步让每一组的优势之和恒为 0**，因此全局 advantage 均值在理想情况下恒为 0；"除以标准差"这一步则在组内方差小的时候放大优势、方差大的时候压缩优势，从而把"组内难度"编码进了梯度尺度。

**本文数据里的体现**：`critic/advantages/mean` 的绝对值只有 `critic/advantages/min` 绝对值的 **0.36%~2.81%**；它的下限 −0.0142（pro 第 14 步）相对展布 [−1.67, +1.33] 完全可以忽略。而 `critic/advantages/max` 在两个 run 都不显著变化（p=0.64 / 0.69），`critic/advantages/min` 在 flash 显著下行（p=0.003）。**所以"优势下降"的正确读法是"负端展布变宽"，不是"均值下移"。** 同时熵在两个 run 都显著上行（p<1e-8），与"组内标准化在低方差组上放大优势"的方向一致。

**可迁移判断规则**：任何用组内基线/标准化的算法，**不要用 advantage 的 mean 做趋势判断**（它被构造钉在 0 附近），要看分布的两端或标准差。反过来，**当 advantage 的 mean 开始显著偏离 0 时，那才是异常信号**——它意味着基线估计与实际奖励分布脱节（典型原因是组被截断、批内混入了不同 n 的组、或者 reward 分布本身在漂移）。本文两个 run 的 mean 都还在 0.03 以内，属于正常。

### 概念 4：判分后处理的"松紧"要用可复算的口径读，不能用"通过率"读

**定义**：判分流水线除了打分，通常还有一层后处理（按系数缩放、重归一化、裁剪）。"判分变松/变紧"要看**这些系数的走向**，而不是看最终通过率——通过率同时受模型能力和后处理影响，不可分辨。

**本文数据里的体现**：`select_factor_mean` 在两个 run 都显著下降（pro r=−0.767, p=1.2e-5；flash r=−0.407, p=0.026），`select_renorm_k_mean` 在 pro 显著上升（r=0.854, p=1.1e-7），两者乘积稳定在 0.98 附近（不是 1，有 1.5%~1.9% 的缺口）；五维档位绝对分显著下降。**这三条方向一致地指向"判分更保守"，而不是"判分放水"。**

**可迁移判断规则**：要判断判分侧松紧，按这个顺序找证据：(1) **档位/维度绝对分的均值**（有没有整体下移）；(2) **后处理乘子与其重归一化补偿**（乘积是否守恒、各自在往哪走）；(3) **失败率/过期率/端到端成功率**（产能有没有变化）；(4) 最后才看"通过率"或"超过参考解的比例"，并且**必须承认它无法区分能力和判分**。本文的 (1)(2) 指向收紧、(3) 平稳，所以 (4) 的解释空间被压缩到"不能证明放水"，但也仅此而已。
