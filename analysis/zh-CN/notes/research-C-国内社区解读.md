## 二、结论先给

1. **中文社区对这块看板的解读质量分化极大，最扎实的两篇都在知乎**：王鹏LLM《把RL训练直播给全世界看：小米 MiMo-V2.6 实时面板深度拆解》（20 赞同）做了指标全景与 recipe 反推；vibe life《MiMo-v2.6 RL 训练看板 · 指标定义与术语解释》（67 赞同，2026-09-19 10:08 编辑）把约 2019 个 tag 做成指标字典并给了实时读数健康度判读。这两篇是"能用"的材料，其余大量是 36氪系/自媒体的"每小时 3 万美元"复述。（我方实测：两页均已打开）

2. **被反复提及的"编程任务生成长度从 80k 突增到 120k"，出处找到了，但中文社区只转述、没有解释**。原话来自前康奈尔教授、参与过 Cursor 模型研发的 Sasha Rush，字母榜的报道写："他自嘲，看一项编程任务的响应长度，看出了赌徒上头的感觉，随后又对数字的变化犯起嘀咕：'从80k跳到120k，这个幅度感觉太大了。'"（官方二次：中文媒体转述海外研究者 X 发言）中文社区自己的长度观察是"平均上下文接近/突破 10 万 token"，没有人把 80k→120k 与长度膨胀刷分、reward hacking 连起来讨论。

3. **确实有人从看板算过卡数**。技术论坛"抡锤者"有人写："btw：cost消费是一个常数，pro是5.71美金/秒，flash是2.85美金/秒。结合商电1人民币/度，5090租金4美元/小时算。大概就是pro模型等效5000张5090，flash模型2500张5090。"（一线经验）我方复算：5.71×3600÷4≈5139 张，2.85×3600÷4≈2565 张，与该帖结论一致。作为交叉参考，罗福莉在访谈里说过训练 MiMo-V2-Pro 和 Flash"各自需要几千张计算卡"（官方二次，字母榜转述）。

4. **看板的"累计成本"不是实测计费，而是固定速率乘时间**。抡锤者同一帖明确写"cost消费是一个常数"；知乎深度拆解也记下 pro `$5.71/秒`、flash `$2.86/秒` 这两个恒定速率。据此算出的"每小时 3.08–3.09 万美元"被几乎所有中文报道当成花费事实引用，但没人说明它是按速率推算的账单、且在重启等待期间照常累加。（一线经验 + 我方实测复算）

5. **质疑集中在三处，且都比媒体标题清醒**：UCSD 副教授 Yu-Xiang Wang 要求记录训练中的问题；markhuang 的中文分析说"离审计还差得远"，架构、参数量、数据配方、许可证、model card 一个都没给；知乎高赞回答 mix.jinny（674 赞同）直接说"感觉flash这边有点overfit"。对"跑分能不能信"，ic.work 列了 DeepSWE 的两条硬伤：SWE-bench Verified 存在数据污染隐患，DeepSWE 初始版有 4 个参考方案没通过自身验证器。（一线经验 / 官方二次）

6. **中文报道之间的数字打架，其中一处是量子位把对比基线写错了**。量子位知乎专栏写"（对比DeepSeek-Flash v1.1是74.2%）"，而 ic.work 给的表是 DeepSeek-V4-Flash 约 53%、DeepSeek-V4-Pro 约 63%、"最高环境配置可达74%左右"。74.2% 更像高配环境下的 Pro 成绩，被挂到了 Flash 名下。（我方实测：两页原文对比）

### 3.1 知乎：一篇深度拆解 + 一个高热度问答 + 一本指标字典

**王鹏LLM《把RL训练直播给全世界看：小米 MiMo-V2.6 实时面板深度拆解》**（发布于 2026-09-18 01:00，湖北，20 赞同）。数据快照标为"2026-09-17 深夜（北京时间）"。核心数字（官方二手，经其 API 抓取）：

- 累计成本合计 `$1,599,638`；pro `$1,098,877`（`$5.71/秒 ≈ $20,556/小时`），flash `$500,761`（`$2.86/秒 ≈ $10,278/小时`）。
- 累计 token：pro 32.5B，flash 49.4B；两线合计 81.9B，摊到 `$19.5 / M token`。文中写"两条线合计 ≈ $30,834/小时，与媒体报道的'每小时约 3.09 万美元'吻合"。
- 每 step 训练 batch 为 `1,568 prompts × 16 rollouts = 25,088` 条轨迹；`train/verdicts/trained` 恒等于 25,088。
- 平均轨迹上下文：pro `72k → 106k` tokens，flash `71k → 129k` tokens；上下文上限 1,048,576。
- 并发沙箱 `env/active`：pro 约 22,400–31,100，flash 约 37,300–39,300。
- 指标重心在惩罚与数据管线：`penalty/` 535 个 tag（其中 523 个属于 `stage_credit_group`）、`critic/` 324、`actor/` 257、`partial/` 327。
- 反作弊相关：`select_hack_attempt_rate ~0.38`（"被标记为'疑似投机取巧'的尝试占比"）、`select_hack_attempt_ge_min_rate ~0.04`；判定耗时 `scg/time_total_sec_mean 510 ~ 655 s`，作者评论"判代码比跑代码还贵！"
- 它给出的一条可迁移判断规则值得记：**看一个 RL 系统成熟不成熟，先看指标重心在哪里**——MiMo 的 loss 类指标只有几个，一半以上指标在监控数据质量、异步一致性和奖励可信度。

## 四、四个特别关注的问题

### 4.1 "生成长度 80k→120k"：出处找到了，解释没找到

先说结论：**这句话不是中文社区原创，是中文媒体转述 Sasha Rush 的 X 发言；中文社区没有对这次突增给出机制解释，也没有人把它接到长度膨胀或 reward hacking 上。**

## 八、术语速查表

| 术语 | 一句话人话解释 |
|---|---|
| RL（强化学习）后训练 | 模型预训练完之后，让它反复做题、按得分调整参数，把"做对"的行为变多 |
| rollout | 模型对同一道题的一次完整尝试（可能包含几十轮工具调用），不是"一问一答" |
| dynsam / `avg@n` | 动态采样器；`avg@n` 是"每道题试 n 次，成功几次，再对所有题取平均"，看板首页那条主曲线 |
| staleness（陈旧度） | 这条样本是用"几个版本之前的模型"生成的；越大表示数据越旧、越偏离当前策略 |
| partial rollout | 一条长轨迹生成不完，跨好几个模型版本接着跑，于是产生陈旧度 |
| train_infer_diff | 采样用的推理引擎和算梯度的训练引擎，对同一个 token 算出的概率不一样，这个差就是它 |
| TIS（截断重要性采样） | 给上面那种"两边算得不一样"的 token 权重设上限，防止几个离群 token 把梯度带崩 |
| GRPO / DAPO | 一类不用额外价值网络的 RL 算法；DAPO 的"动态采样"就是扔掉全对和全错的题（组内没有区分度） |
| passrate/zero、passrate/one | 一组 16 次尝试里全错、全对的题目占比，这两种都会被丢掉不训练 |
| grader compute | 花算力去判分：跑测试用例、按评分细则打分，本身也是一大笔开销 |
| credit assignment（信用分配） | 一条轨迹几十步，最后成功了，到底哪几步该记功、哪几步是多余的——把功劳分到步骤上 |
| reward hacking | 模型钻奖励函数的漏洞拿高分，但没真正完成任务 |
| `ctx_total_length` | 输入加输出的总长度（token 数），看板上它约 10 万且在涨 |
| harness | 模型执行任务用的那套"外壳"：能开终端、改文件、跑测试的工具体系；不同任务用不同 harness |
| checkpoint | 训练途中存下来的模型快照；离线评测就是拿这些快照去跑分 |
| SWE-bench Verified / DeepSWE v1.1 | 两个考"改真实代码仓库、修真实问题"的基准测试；后者是这次看板用的那个 |
| `avg@3` | 同一道题跑 3 次取平均，减少单次运气成分 |
