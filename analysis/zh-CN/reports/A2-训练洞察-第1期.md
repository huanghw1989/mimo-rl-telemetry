# mimo-v2.6 RL 训练洞察（第 1 期）

数据截止：2026-09-17 10:50 UTC（北京时间 18:50）。pro 到第 14 步，flash 到第 18 步。
全部数字来自站点公开接口的原始数据，核对过程见 `notes/05-数值核查与派生量.md`。

---

## 摘要

1. 两次训练都在稳定变好，速度大约是**每一步涨 0.5 个百分点**的通过率（pro 斜率 0.0049/step，flash 0.0057/step），
   相关系数都在 0.94 以上，趋势很干净。
2. 瓶颈已经从"生成"转移到"训练"。pro 的生成耗时下降了 16%，训练耗时涨了 67%，
   而训练耗时和上下文长度的相关系数是 0.968，几乎是直线关系。这不是巧合，是长上下文 agentic RL 的必然结果。
3. 能力增长的结构值得警惕：pro 这 5.06 个百分点的进步里，**有 4.86 个点被"中间池子缩小"这件事吃掉了**，
   真正来自"中等题变好"的只有 2.06 个点。有大约 15% 的题从头到尾一次都没做对过，14 步里没动过。
4. 上下文长度涨了 47%（pro）和 61%（flash），而题目长度几乎没变。多出来的全是模型自己写的，
   平均一道题写 10 万 token、来回 60 轮。
5. 异步管线目前是健康的：平均数据过期 1.2 代，重要性采样被裁剪的比例只有万分之三。
   首页那条"训练器与推理引擎分歧"的曲线看起来涨了 3 倍，但拆到按数据新鲜度分的 8 个桶里就会发现，
   **新鲜数据上的分歧几乎没动（只在 0.0022 到 0.0033 之间），涨的全是数据变旧带来的加权效应。**
6. 离线评测的信噪比不高。DeepSWE 单步波动能到 6 个点，跟在线通过率的相关系数只有 0.48（pro 的逐步增量）。
   看这个指标必须看两三步的连线。
7. 工程可靠性是当前最大的隐性成本：pro 有 **33% 的机时没有落在一个已完成的 step 里**，
   这段时间仍然在按每秒 5.71 美元计费。

## 一、成本与吞吐：钱花在哪

站点给的成本速率是 pro 5.71 美元/秒、flash 2.855 美元/秒，两者相加是 8.565 美元/秒。
换个说法：**这个看板每秒钟烧掉 8.57 美元，每小时 3.08 万美元，每天 74 万美元。**

用速率乘以每一步的墙钟时间，可以得到每一步的成本（这会把重启等待也算进去，是上界）：

| | 单步成本区间 | 单步训练 token | 每百万训练 token 成本 |
| --- | --- | --- | --- |
| pro | 3.9 万 ~ 6.0 万美元 | 1.7B ~ 2.7B | 约 22 美元（19.5 ~ 30.3） |
| flash | 1.4 万 ~ 2.9 万美元 | 1.8B ~ 2.8B | 约 8 美元（7.1 ~ 12.0） |

这两个数放在一起看才有意思：**pro 的每 token 训练成本大约是 flash 的三倍**，
但两边的单步 token 量差不多。也就是说钱的差别几乎全在"同一个 token 要多少张卡来算"上，
而不是在"做了多少事"上。这是模型规模差异最直接的体现。

还有一个趋势值得记下来。把每步的"训练器耗时 ÷ 训练 token 数"算出来当效率指标：

- pro：从第 3 步的 1.49 秒/百万 token 涨到第 14 步的 1.82，涨了 22%。
- flash：从第 1 步的 1.05 涨到第 18 步的 1.46，涨了 39%。

训练器处理同样数量 token 的速度在变慢，flash 变慢得更厉害。原因大概率是序列变长以后，
注意力部分的计算量增长快于 token 数的线性增长，另外长序列对显存和通信的压力也更大。
这条曲线如果继续往上走，会直接吃掉上下文变长带来的收益。

## 二、瓶颈的迁移：从生成到训练

这是第 1 期里我最想让人看到的一条。

pro 的完整耗时变化（第 1 步 → 第 14 步）：

- 整步耗时：9570 秒 → 10492 秒，涨了 9.6%
- 生成阶段：6514 秒 → 5451 秒，**降了 16.3%**
- 训练器阶段：2889 秒 → 4814 秒，**涨了 66.6%**

同期训练 token 量涨了 47%。也就是说：

- 生成阶段几乎不受 token 量增长的影响。这很好理解，生成是并行铺开的——
  pro 有大约 2.3 万个沙箱同时跑，生成本身要多久取决于"最长的那条轨迹跑了多久"，
  而不是"总共要跑多少 token"。所以 token 涨了 47%，生成时间反而降了。
- 训练器阶段几乎正比于 token 量。我把上下文长度和训练器耗时做相关，系数是 0.968。

再看一个佐证：一步的时间里，生成 + 训练之外的部分只占 2.3%（pro）/ 3.0%（flash）。
也就是说**一步的时间里没有被浪费在调度上，全部时间是这两个阶段**。
那么整步时间的走向就完全由这两个阶段的角力决定。

按现在的斜率，pro 每步训练器耗时以 130 秒/step 的速度涨，生成耗时基本持平。
大约再过 10 到 15 步，训练器就会超过生成，成为单步时间的主导项。
那时候单步耗时会突破 3 小时，而生成阶段会开始出现大量空闲算力。

这件事的工程含义很明确：**继续靠"让模型多写"来提升成绩，边际成本会越来越高**。
在第二期我会盯着这条线，看团队有没有做干预（比如缩短上下文、增大生成并发、优化训练侧）。

## 三、能力增长的结构：把 5.06 个百分点拆开

前面说过，一道题做 16 次，如果全对或者全错，这 16 次之间没有差异，
产生不了学习信号，这道题就白采样了。这个约束让"通过率的提升"有了结构。

把每一步的采样池拆成三块：全错（比例 p0）、全对（比例 p1）、以及中间（比例 1-p0-p1，平均通过率 m）。
平均通过率就等于 `p1 + (1-p0-p1) × m`。对首末做差分：

pro 从第 1 步到第 14 步，avg@n 涨了 +0.0506，拆开是：

| 来源 | 贡献 |
| --- | ---: |
| 全对题目的比例上升（p1: 0.178 → 0.256） | **+0.0786** |
| 中间池子缩小（因为题目被推到全对了） | −0.0486 |
| 中间池子里的题本身变好（m: 0.572 → 0.605） | **+0.0206** |
| 合计 | +0.0506 |

flash 的拆解（第 1 步 → 第 18 步，总涨 +0.0886）：

| 来源 | 贡献 |
| --- | ---: |
| 全对题目的比例上升（0.121 → 0.226） | +0.1049 |
| 中间池子缩小 | −0.0597 |
| 中间池子里的题本身变好（0.547 → 0.612） | +0.0434 |

读法：

- 两次训练最大的单一驱动力，都是**把"原来对一半"的题推成"次次都对"**。
  这是好消息，说明模型在已经摸到门槛的题上确实变稳了。
- 但"中等题本身变好"这个更本质的部分，pro 只贡献了 2.06 个点，flash 贡献了 4.34 个点。
  **flash 的进步结构比 pro 健康**——它更多是在真正的中间地带提升，而不是把边界上的题推过去。
- 最刺眼的是 p0。pro 的全错比例 14 步里从 0.146 到 0.150，flash 从 0.161 到 0.159，
  **两次训练都纹丝不动**。有大约 15% 的题目，模型从头到尾一次都没做对。

从相关性上也能看出同一件事：通过率和全对比例的相关性是 +0.93（pro）/+0.95（flash），
和全错比例只有 −0.47 / −0.30。

**结论**：这两次 RL 训练到目前为止，主要是在"会一点的题上变得稳定"，
而不是"攻克完全不会的题"。15% 的硬骨头是这批题的难度上界，也可能是当前奖励设计覆盖不到的地方。

第二期要验证的是：随着训练继续，这个 15% 会不会开始松动。
如果一直不动，说明数据里存在一批**当前策略永远拿不到非零优势**的样本，
它们在每一步都在消耗采样预算却不产生梯度。

## 四、长度的军备竞赛与它的天花板

数据：

| 指标 | pro step1 → step14 | flash step1 → step18 |
| --- | --- | --- |
| 平均总上下文 | 72,178 → 106,203（+47%） | 71,634 → 115,604（+61%） |
| 其中题目部分 | 4099 → 4210（+2.7%） | 4171 → 4370（+4.8%） |
| 其中模型自己写的 | 68,078 → 101,993（+50%） | 67,463 → 111,233（+65%） |
| 平均回合数 | 47.5 → 59.5 | 47.3 → 63.2 |

题目几乎没变长，涨的全是模型自己生成的内容。而且回合数只涨了 25%~34%，
上下文却涨了 47%~65%，说明**每一轮本身也在变长**。

这不是"模型变啰嗦"。在 agentic 任务里，模型每做一步都要把观察结果（文件内容、命令输出、报错信息）
读回上下文，这些内容会一直累积。上下文越长，它能"记住"的现场信息越多，通过率也越高——
上下文长度和 avg@n 的相关系数是 +0.91（pro）/+0.85（flash）。

但这条路的代价是硬的：

- 训练 token 量正比于上下文长度（我验证过：1568 题 × 16 次 × 平均上下文 = 单步 token 总量，误差 1%~3%）。
- 训练器耗时正比于训练 token 量（相关系数 0.968）。

所以**上下文每长 1%，训练成本就贵 1%**，而且第 1 节算过，单位 token 的训练效率本身还在变差。

天花板上限是 1,048,570 个 token。站点没有解释这个数字，但它明显是个硬性的上下文上限
（非常接近 2 的 20 次方）。被截断的轨迹比例 `ctx_total_length/clip_ratio` 目前是万分之几，
绝对值很小，但两边都在往上走（pro 从 4.0e-5 到 2.4e-4，flash 最高的第 18 步到了 1.4e-3，
也就是千分之 1.4）。按长度现在的增长速度，这条线值得每期都看一眼。

另外一个细节：flash 第 14 步出现过一条 2,236,430 token 的轨迹，是上限的两倍多。
这属于异常样本，站点没解释，我也不猜它是什么。

## 五、异步管线的稳定性评估

这几条线是判断"训练学到的方向对不对"的关键，因为它们反映的是
"用来算梯度的数据，和当前模型有多不一致"。

### 数据过期程度

平均过期代数：pro 稳定在 1.0~1.8，最近几步是 1.2；flash 1.7~1.9，第 18 步回落到 1.14。

但平均值会掩盖分布。pro 第 14 步的分布是：

| 过期代数 | token 占比 |
| ---: | ---: |
| 0（新鲜） | 27.4% |
| 1 | 38.5% |
| 2 | 19.5% |
| 3 | 14.6% |

**七成以上的训练数据不是当前策略产生的。** 这是异步 RL 的正常代价，不是故障。
需要特别说明的是，**过期程度低不等于好**：公开的框架文档里有一组 128 卡对照实验，
把允许的过期程度从 0 放宽到 0.5，最终精度从 0.2604 升到 0.3094，
同时 400 步的耗时从 26 小时降到 17.3 小时。原因是生成和训练重叠起来跑，机器不空转，
只要重要性采样修正确实生效，稍旧的数据完全划得来。
所以要把"过期"理解成一种用偏差换吞吐的交易，而不是一个要被压到 0 的指标。
真正要警惕的是它持续涨到 3 以上还不回落。

flash 的尾巴更长：第 11 到 15 步，有 0.33%~0.47% 的 token 过期 8 代以上，
连站点给的 8 个分箱都装不下。这是我算 `Σ i × frac_i` 会比站点报告值小的原因，
也说明 flash 的异步管线深度比 pro 更大。

### 重要性采样修正的压力

过期数据要按新旧策略的概率比做加权修正，同时把权重限制住，防止个别样本权重失控。
站点暴露了 `actor/pg_tis_clipfrac`（被限制住的样本比例）和一组 `F(tau=…)`（不同阈值下的超界比例）。

| | 第 1 步 | 末步 | 量级 |
| --- | ---: | ---: | --- |
| pro `pg_tis_clipfrac` | 2.1e-5 | 3.3e-4 | 万分之三 |
| flash `pg_tis_clipfrac` | 4.5e-5 | 1.9e-4 | 万分之二 |
| pro `F(tau=1.5)` | 0.39% | 2.39% | 百分之二 |
| flash `F(tau=1.5)` | 0.60% | 2.10% | 百分之二 |

涨幅都不小（十几倍到几倍），绝对值都很小。判断是：**过期数据带来的偏差目前还压得住**。
这跟平均过期代数只有 1.2 是对得上的——如果过期代数涨到 3 以上，这几条线会先报警。

值得留意的是这些数在**重启之后会掉回去**（flash 第 16 步的 `pg_tis_clipfrac` 只有 4.0e-5，
是第 15 步的五分之一）。原因是重启后所有在途的采样都作废了，第 16 步的数据几乎全是新的。
这也说明这几条线对管线状态很敏感，是一个好用的事故探针。

### 训练器与推理引擎的数值分歧

`train_infer_diff/new_infer/kl` 衡量的是同一段文字，推理引擎算的概率和训练器算的概率差多少。

表面上的数字很吓人：

- pro：0.0022 → 0.0094，涨了 3.3 倍
- flash：0.0029 → 0.0083，涨了 1.9 倍
- 绝对差均值 `diff_abs_mean`：pro 0.024 → 0.046；flash 0.027 → 0.044

**但这条曲线不能直接读，因为它是个混合物。** 看板把同一组指标按数据的新鲜度分成了 8 个桶
（`partial/0/…` 是新鲜数据，`partial/1/…` 是过期一代，以此类推）。
我把这些桶和它们的占比乘起来做了核对：

```
全局 KL = Σ (第 k 桶的 token 占比 × 第 k 桶的 KL)
```

这个等式在 pro 的 13 个有数据的 step 上、flash 的 16 个 step 上，误差都在 2% 以内。
也就是说，**首页那条 KL 曲线只是各桶的加权平均，不是一个独立的量**。

把桶拆开看，结论完全变了：

| | pro | flash |
| --- | ---: | ---: |
| 新鲜数据（第 0 桶）的 KL，首步 → 末步 | 0.00219 → 0.00248（+13%） | 0.00287 → 0.00333（+16%） |
| 全局 KL，首步 → 末步 | 0.00219 → 0.00937（+328%） | 0.00287 → 0.00834（+191%） |
| 新鲜数据的 `diff_abs_mean` | 0.0238 → 0.0254（+7%） | 0.0271 → 0.0300（+11%） |
| 全局 `diff_abs_mean` | 0.0238 → 0.0459（+93%） | 0.0270 → 0.0444（+64%） |

再看相关性：全局 KL 和平均过期代数的相关系数是 **+0.944**（两次训练都是），
和"新鲜数据占比"是 **−0.877 / −0.722**，和"第 0 桶自己的 KL"只有 **+0.331 / +0.151**。

**结论：首页那条 KL 涨了 3 倍，绝大部分不是两个引擎越走越远，而是数据变得越来越旧。**
真正衡量"引擎本身差多少"的那个量——新鲜数据上的 KL——几乎是一条水平线。

那这条水平线是多少？pro 约 0.0022~0.0025，flash 约 0.0029~0.0033。
这个量级是"同一个策略、同一个模型，两个不同实现算出来的概率能差多少"的数值地板。
公开资料里，同一个推理引擎重跑两次的 KL 就有 8.4e-4 量级，
MoE 模型因为专家路由的离散性还要更高一些（约 1.5e-3）。
看板实测的 2.2e-3 ~ 3.3e-3 和这个量级是吻合的，看不出异常。

剩下的那部分增长是真实的：第 1 桶的 KL 从 0.0045~0.0056 涨到 0.0075，
第 2 桶从 0.011 涨到 0.013，第 3 桶从 0.017 涨到 0.023，涨幅在三到五成。
过期一代的数据，两个引擎的分歧确实在缓慢变大——这符合"策略离初始点越远、路由越分散"的预期。

一个额外的用处：因为这个分解存在，只要盯着第 0 桶的 KL 是不是还在 0.003 以下，
就能把"引擎坏了"和"数据旧了"这两件事分开。这是一条比看首页曲线可靠得多的报警线。

顺带说一个没成立的猜测。公开资料里有一种说法：
训练器与推理引擎的分歧变大时，梯度范数会出现同步尖峰。我拿数据对了一下，**这条不成立**：
pro 的相关系数是 +0.336，flash 是 **−0.456**。两次训练里巧合的是 pro 第 9 步
`grad_norm`（0.00873，全run最高）和 KL（0.00980，全run最高）确实同时登顶，
但 flash 的 `grad_norm` 峰值出现在第 16 步——那正是重启后重跑的那一步——
而 KL 峰值在第 11 步，两者不重合。所以第 9 步那个同步更可能是巧合，
不适合当成通用的交叉验证手段。flash 第 16 步的梯度尖峰，更可能的原因是重启后重跑带来的批次变化。

顺带记一个之前没说清的：`actor/lr` 在整个 run 里恒为 3e-6，从头到尾没变过。
学习率是固定值，没有 warmup 和衰减。

### 被裁剪掉的样本

`actor/pg_clipfrac` 和 `actor/ppo_kl` 在两次训练的所有 step 里都精确等于 0。
标准 PPO 里 clipfrac 应该是一个大于 0 的小数，恒为 0 不正常。
可能这套系统用的裁剪机制不是标准 PPO（所以这个计数器没被赋值），也可能是配置里关掉了。

**我不确定是哪个原因，站点也没有说明，所以不在这一期下任何判断。**
只记一个操作层面的结论：不要用这两个指标判断这套训练的健康度，它们在这套系统上恒等于 0。

## 六、离线评测的信噪比

DeepSWE v1.1 目前只有这一项离线评测。把在线通过率和它放一起：

pro（10 个有评测的 step）：水平相关系数 +0.804，**逐步增量的相关系数只有 +0.484**。
flash：水平 +0.792，逐步增量 +0.584。

翻译一下：这个基准能反映长期趋势（水平相关 0.8），但**不能用来判断"上一步的训练有没有效果"**。
flash 从第 10 步的 60.18 掉到第 11 步的 54.13，再回到第 12 步的 60.77，
一步之差 6 个点，而这三步的在线通过率变化只有 1 个百分点以内。

另一个容易被忽略的事实：第 1 步的 DeepSWE 成绩 pro 已经是 58.41、flash 48.67。
这是**本轮 RL 开始之前的基础模型水平**。11 步之后 pro 到 65.78，涨了 7.4 个点。
所以这一轮 RL 是在一个已经不错的基线上继续爬，不是从零开始。

对读者的实用建议：看 benchmarks 这一栏，把它当"每周体检报告"看，
不要当"每次训练的验收单"看。

## 七、奖励校验流水线：量得多、改得少

`penalty/stage_credit_group` 这一族有 535 个指标，是最大的一族。
从字段名能看出一条相当复杂的代码题奖励校验流水线：判定池、两趟判定、分组、分级、疑似作弊检测。

能确认的数值事实：

- 判定本身很可靠：`pass1_success_rate` 稳定在 0.95 以上，`pass2_success_rate` 恒等于 1.0。
- 一堆保护性的上限计数器从来没触发过：`select_r2_capped`、`keep_mass_capped`、
  `rollouts_masked`、`select_r3_gold_fails`、`groups_skipped_unbalanced` 全部恒等于 0。
  其中 `select_r3_gold_fails = 0` 意思是"标准答案通不过新生成的测试"这件事一次都没发生过，
  说明自动生成的测试没有出现严重的假阴性。
- 疑似作弊检测的触发率很高：`select_hack_attempt_rate` 在 pro 是 0.34~0.41，flash 是 0.38~0.47。
  但真正被标为严重的 `select_process_severe` 每步只有 15~30 条。
  字段名里的 "attempt" 到底算"触发检查"还是"确认尝试"，站点没说明，我不下结论。
- 分级比例很稳定：T1 约 64%、T2 约 33%、T3 约 0.8%、H 约 1%。

最值得说的是最后一条。站点的 `train/adv_pos_sum_pre_penalty` 和
`train/adv_pos_sum_post_penalty` 每一步的数值**完全相同**，
`penalty/action/adv_reduction_total` 恒等于 0。
也就是说，这套看起来很复杂的惩罚流水线，**量得很细，最后几乎没有真的改动优势值**。

这有两种读法。一种读法是好的：保护机制不生效，说明模型目前没有严重的作弊行为，
流水线只是保险。另一种读法是：这么高比例的"疑似作弊"触发率，
可能只是检测器过于敏感，真正需要干预的信号被淹没了。

我倾向于第一种，但只有一条证据支持：真的严重的 `select_process_severe` 每步只有十几到三十条，
占总量的千分之一量级。第二期会继续跟这条线，看 `select_hack_attempt_rate` 会不会随训练上升
（作弊率随时间上涨是 RL 的常见现象）。

## 八、可靠性：三分之一的机时没有变成 step

pro 从启动到现在跑了 48.3 小时，14 个已完成的 step 加起来只占 32.3 小时，
**中间 16 小时（33%）没有落在任何一个有记录的 step 里**。
flash 是 43.6 小时里有 8.7 小时（20%）。

这段时间按每秒 5.71 / 2.855 美元计费。粗略算，pro 那 16 小时大约值 33 万美元，
已经超过 flash 全部花销的一半。

这些时间去了哪里，从数据里能看到一部分：

- pro 重启了 6 次，flash 重启了 2 次。公告里提到的原因有节点显存问题、
  以及"某类基础设施错误在数据集上没有被告警，持续了 3 小时"。
- `train/verdicts/expired`（超时作废的轨迹）在 pro 是每步 0~1488 条，波动很大。
- `env/total_error` 每步在 0~162 之间增长，重启后归零（说明它是自上次重启以来的累计值）。

一个有意思的细节：**单步时间并没有因为重启而变短**。
flash 第 16 步用了 10,193 秒，是它所有 step 里最长的——那正是重启后重跑的那一步。
原因大概是重启后所有沙箱要重新预热、所有在途轨迹要重跑，前半段机器是半空的。

结论：对这类长时间 RL 训练来说，**稳定性本身就是成本项**，
而它的量级（20%~33% 的机时）比大多数人预想的要大。看板把重启和公告都摊开，这一点做得很实在。

## 九、pro 与 flash 的对比

把两边放在一起，能看出"模型规模差一倍"会带来哪些结构性差异：

| | pro | flash |
| --- | --- | --- |
| 成本速率 | 5.71 美元/秒 | 2.855 美元/秒 |
| 沙箱并发 | 约 2.3 万 | 约 3.8 万 |
| 每百万训练 token 成本 | 约 22 美元 | 约 8 美元 |
| 通过率起点 → 当前 | 0.565 → 0.615 | 0.514 → 0.602 |
| 通过率涨幅 | +8.9% | +17.2% |
| 全对比例涨幅 | +44% | +87% |
| 中间池子变好的贡献 | +0.0206 | +0.0434 |
| 基础设施错误率 | 0.3%~0.9% | 0.6%~1.4% |
| 重启次数 | 6 | 2 |
| 数据过期代数 | 1.0~1.8 | 1.7~1.9 |
| 投机解码接受长度 | 3.41~3.55 | 2.75~2.86 |
| DeepSWE 起点 → 当前 | 58.41 → 65.78 | 48.67 → 60.77 |

几点观察：

- **flash 的涨速是 pro 的两倍**（17.2% vs 8.9%）。这符合预期：起点低的模型可学的空间更大。
- 但 flash 的稳定性明显更差：基础设施错误率是 pro 的两倍，
  数据过期代数更高（1.7~1.9 vs 1.0~1.8），通过率曲线也更抖（第 2 步掉到 0.496 又拉回来）。
- flash 的投机解码接受长度只有 2.76~2.86，pro 有 3.41~3.55。
  两个都在缓慢下降。接受长度下降意味着推理解码的加速比在变差，
  这跟"生成时间没有随 token 增长"是有关系的——生成端能维持住时间，一部分功劳要归给这些加速手段的效率。
- 沙箱并发数 flash 比 pro 多 65%，但 flash 的基础设施错误率反而更高。
  说明错误率不是并发度单一因素决定的，可能跟 flash 用的任务类型分布不同有关。

## 十、第 2 期要盯的几条线

按优先级排：

1. **全错比例（`dynsam/passrate/zero`）会不会松动。** 这是判断"模型有没有真的在攻克难题"的唯一直接证据。
   如果到第 20 步还在 0.15 附近横盘，就需要怀疑数据里有一批策略永远拿不到优势的样本。
2. **训练器耗时是否超过生成耗时。** pro 的斜率是 130 秒/step，生成基本持平，交叉点在 10~15 步之内。
3. **新鲜数据（第 0 桶）的 KL 有没有突破 0.004。** 现在 pro 0.0025、flash 0.0033，都还在数值地板的量级。
   不要再看首页那条全局曲线，它会因为数据变旧而涨，跟引擎好坏没关系。
4. **上下文长度的天花板。** 被截断的比例是不是还在涨。
5. **`select_hack_attempt_rate` 会不会随训练上升。** 作弊率随训练上涨是 RL 的常见现象。
6. **flash 的基础设施错误率。** 已经涨到 1.39%，而且它已经因为未告警的基础设施错误重跑过一次。
7. **离线评测会不会出现新的基准项。** 现在只有 DeepSWE 一项，样本太少，
   一个基准的波动无法区分"真变化"和"评测噪声"。
